# 定时发送额度与余额变化

定时发送额外额度只来自桥接已有的日程、时间冒泡、用户约定联系、API预算事件，或成功认领发送凭据的固定通知。聊天里写“定时消息”不会授予额度。调度中心、事件拥有组件与发送账本各自保留原有职责。

同批多项定时事件每项可发一条，最多20项，临时额度有效2分钟。分钟或小时发送限额已满时仍可使用这一次性额度，但每会话滚动一小时最多额外20次物理发送。所有实际发送和结果未知的预占仍进入普通限频统计，普通聊天没有额外权限。已用事件不能靠读取、换回合或重载续领；排队、睡眠后在真实出站前再次核对期限。未使用的临时额度过期后，仍有效的事件只能按普通限额处理。

这项例外不改变账号Token预算、模式、白名单、免打扰、宵禁、事件过期、跨会话目标及媒体权限。API预算事件仍限管理员私聊的一条文字；固定通知仍须认领持久发送凭据，未知结果不自动重发。

余额查询继续复用15秒并发缓存，普通闲聊不增加查余额的次数。每次成功查询先保存lastSuccess，按同一基准判断低额跨档、归零、补充/恢复或明显消耗。显式手动查询可立即后台尝试反馈，不等下次巡检，也不等待LLM投递才返回查询结果。普通自动变化在冷却期间保留并合并，紧急变化立即尝试。查询失败保留旧成功值和待发预警，标记未核实，下一次成功核对后再发；未知不会变成0。

“立即尝试”不是送达保证：会话繁忙、暂停、免打扰、账号预算或底层连接可能阻止投递。只有实际QQ成功回执才记为已发送。测试使用临时状态、模拟模型及QQ，不向真实联系人发送测试消息。
