# 定时发送额度与余额变化

2026-11-02起，显式任务执行、传话、日程创建/修改/取消及真实到期提醒、报告查看/检索/摘要和完成汇报按任务组处理：接手同任务及其完成汇报整组占共享分钟/小时额度1点，组内实际发送不重复扣点，也不限普通内容拆分条数。这项规则优先于旧定时突发配额，来源须由真实准入和受信任务链证明。任务开始仍检查原有唤醒、费用与弱限频；已准入任务若在执行中跨费用软/硬阈值，可凭持久的原任务权限继续并及时汇报，全部实际花费仍记账。聊天里写“定时消息”或模型自报任务身份不会获得准入或新建已付点任务组。完整规则见 [完整内容与任务准入](REPLY_CONTENT_SCOPES.md)。

普通时间冒泡等非任务定时行为仍使用既有事件额度：每个真实事件一条、单批最多20项、有效2分钟，每会话滚动一小时最多额外20次物理发送；非任务的实际发送与未知预占仍计普通限频。到期任务提醒不受这些旧突发条数配额约束，按任务组接手1点、组内不重复扣点处理。已用事件不能靠读取、换回合或重载续领；排队、睡眠后在真实出站前再次核对期限。未使用的非任务临时额度过期后，仍有效的事件按普通限额处理。调度中心、事件拥有组件和发送账本各自保留原职责。

任务没有可用接手额度时，来源保留已读未处理；额度恢复后自动复查原有唤醒、费用、弱限频、权限和时效等条件，成功占1点后再执行，同组不重复扣点。持久的任务接手计点记录独立于QQ实际发送凭据，接手不等于送达；只有真实成功回执能确认已发送，未知结果不伪造成功或自动重发。

原任务执行续权不等于新任务费用豁免；新建任务仍检查适用的费用和弱限频，非任务定时行为保留原有预算规则。模式、白名单、免打扰、宵禁、暂停、事件过期、跨会话目标、媒体权限、维护回合禁发、防重和真实回执守卫继续生效。API预算事件保留管理员私聊目标与事件自身的一条文字规则；固定通知仍须认领持久发送凭据，未知结果不自动重发。

余额查询继续复用15秒并发缓存，普通闲聊不增加查余额的次数。每次成功查询先保存lastSuccess，按同一基准判断低额跨档、归零、补充/恢复或明显消耗。显式手动查询可立即后台尝试反馈，不等下次巡检，也不等待LLM投递才返回查询结果。普通自动变化在冷却期间保留并合并，紧急变化立即尝试。查询失败保留旧成功值和待发预警，标记未核实，下一次成功核对后再发；未知不会变成0。

“立即尝试”不是送达保证：会话繁忙、暂停、免打扰、未通过任务准入或适用的预算检查、底层连接异常都可能阻止处理。只有实际QQ成功回执才记为已发送。测试使用临时状态、模拟模型及QQ，不向真实联系人发送测试消息。
