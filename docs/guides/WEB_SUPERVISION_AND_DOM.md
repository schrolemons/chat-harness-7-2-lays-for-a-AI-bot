# 网站监督、脚本协同与 DOM 操作

公开版的网站和脚本清单默认留空。填写网址后，首次成功读取会建立基线，之后可向此实例的管理员发送网页变化摘要。页面显示读取、登录、变化和通知状态。「重新监管」只重试选中的网址。

需要登录时，在专用浏览器中完成登录。验证成功后恢复无头检查。不同来源的会话分别保存，同一来源的不同路径可以共用登录。

脚本按登记的地址展示心跳和约定。已接入的脚本可用 `node scripts/script-heartbeat.mjs <脚本路径> <ok|error> [说明]` 报告运行状态。登记本身不会执行脚本。

## 管理员DOM工具与预设

当前owner私聊的管理员开发模式关闭，使用qq-chat-v2，浏览器工具在清单和执行期均被阻止。这是权限设置，不是网页没打开就应当绕过。保持关闭。需要开启时：E层→管理员环境→管理员助手→启用“用于聊天与仿真”，选择实际提供浏览器工具的管理员预设（例如通用开发助手或DSH插件与配置开发；空选项跟随DSH默认）→保存。不要重新引入正在退役的qq-chat-dev重复入口。预设变化会影响会话工具和附加系统规则，但不写回roles目录的人设卡。

Playwright MCP 按需启动独立的 `state/dom-browser-profile`。管理员工具的导航响应可能只给快照文件链接，可以调用 `browser_snapshot` 取得页面正文和当前元素引用，再按实际工具参数执行点击或填表。
