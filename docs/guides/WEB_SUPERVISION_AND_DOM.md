# 网页监管、登录态与DOM操作

## 登录态边界

同一origin（协议、主机、端口）下不同路径共用独立BrowserContext及会话文件。不同主机名，包括不同子域，分别保存Cookie和local/sessionStorage；跳转到同一SSO服务也不能把另一平台的SSO会话导入当前平台。初次迁移仅取目标主机域名精确匹配的旧Cookie，原快照不删除；以后只读取当前平台会话。没有账号密码自动填写或整套日常Edge配置复制。

会话文件位于本机state/campus-site-sessions，按origin哈希命名，不入Git和私人资料快照。讲座API只读取独立导出的campus-lecture-cookies.json，由桥接拥有的campus-lecture-cookies.mjs适配器只取yjs平台的Cookie；不改独立集成仓库的脚本。

## 重新监管

按钮向既有管理员配置接口提交URL和单次nonce，重置该主机的尝试机会；其他网站不重置。空闲时立即仅检查所选URL；后台忙时保留请求，下次调度优先处理，不等全检周期。等待时页面每5秒刷新状态，平时30秒。登录有效就直接后台验证，不弹窗。

确认登录失效后立即通知；每次尝试失败均通知，默认间隔5分钟、最多3次后暂停。手动重新监管、正常恢复后的再次掉线和桥接新进程启动获得新预算；组件重载不重置。网络/HTTP错误单独显示，不把旧页面正文或空结果当成功，不以网络错误猜测需要登录。

通知包含网站名、原网址、最近检测到掉线的时间、恢复验证时间，均为北京时间。掉线时间指检测时刻，不是未经证实的真实掉线瞬间。登录后先验证原平台，再保存独立会话、关闭专用可见浏览器、启动无头并重新验证；讲座还须确认应用列表响应。

## 管理员DOM工具与预设

当前owner私聊的管理员开发模式关闭，使用qq-chat-v2，浏览器工具在清单和执行期均被阻止。这是权限设置，不是网页没打开就应当绕过。保持关闭。需要开启时：E层→管理员环境→管理员助手→启用“用于聊天与仿真”，选择实际提供浏览器工具的管理员预设（例如通用开发助手或DSH插件与配置开发；空选项跟随DSH默认）→保存。不要重新引入正在退役的qq-chat-dev重复入口。预设变化会影响会话工具和附加系统规则，但不写回roles目录的人设卡。

Playwright MCP按需启动独立state/dom-browser-profile，不再附着监管9222，也不依赖9227。普通聊天仍无DOM工具。新版本导航响应可能只给快照文件链接；继续调用browser_snapshot且不传filename，取得页面正文和当前元素引用，再按实际schema调用click/type等工具。
