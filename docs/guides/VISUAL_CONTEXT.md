# 可视化 context

入口：O 层 → 可视化 context。

选会话后，卡片对应这次真实唤醒的组件产出。正文默认折叠；本轮没有内容的模块也在原位占位，显示“本轮暂无内容，位置保留”，编号按完整顺序连续显示。勾选表示允许把这部分内容发给 AI，拖动或 ↑ ↓ 调整同一分组内的顺序。点击“保存所有会话的上下文设置”，从各会话的下一次唤醒开始使用。所选会话只影响预览，设置适用于所有私聊和群聊。

例：停止注入黑话模块，不会停用黑话学习、查询工具或修改来源。重要角色、身份权限、会话令牌与本轮任务有框架保护。固定设定位于前置层，用户消息与记忆事实保持数据身份。

“设置效果预览”使用已捕获的内容展示当前勾选与排序的效果，不重新运行业务钩子、不调用模型。“本轮请求对比”读取同一轮 DSH 发送前的初始、上一次、当前请求。例：本轮调用4次后，保留第1、3、4次；下一轮重新记录。只有一次时初始与当前指向同一次调用，上一次显示尚未采集。不会为了补齐三次调用模型。每次请求都分别带有当时有效的系统设定、消息和 tools 清单；工具清单是与 messages 并列的请求字段，不是历史消息。没有记录时明确说明。字符统计与 token 粗估分开；费用以实际账单为准。例：“回复尽量简短”原来可能在历史中累计出现 10 份，整理后每次调用只带当前有效的一份；真正聊过的话仍保留。

接收端使用正式的 `agent/inbox/claimed`、`system-prompt/assemble`、`agent/pre-step` 钩子。签名包绑定会话；接收端确认就绪之前，桥接继续使用原有可读发送路径。固定设定保持一份；动态信息替换旧快照；新增 QQ 消息按 seq 去重。旧包装通过带来源的 surface replacement 收缩，原始事件不删除，工具调用与结果不动。嘴炮弹药仅实际触发演练时出现，不在冒泡、日程等后台回合常驻。

源码：`plugins/qq-components/obs-context-assembly/` 拥有编排规则、签名、历史投影与证据；`plugins/qq-agent-presets/context-composer.mjs` 拥有 DSH 接入；`src/console/context-management.js` 只做管理端路由；页面位于 `console/layers/O/`。策略为 `state/plugins/config/obs-context-assembly.json`，证据和本地签名密钥为忽略目录 `state/context-assembly/`，密钥不进入私人快照。

验证：`npm run test:context-assembly`；`node scripts/test-context-console.mjs`。有本机 DSH 源码运行库时，`node scripts/test-context-dsh-admission.mjs` 使用脚本模型验证实际 admission 和事件重建，不发生网络请求。`audit-context-replay.mjs --source=<本地会话日志>` 只在副本中演练历史投影。

启用需运行中的桥接加载新版核心，并让 QQ 聊天 preset 加载 context-composer；仅 build 控制台不等于接收端已启用。共享核心的其他工作线仍在修改时，不重启覆盖运行版本；定稿后联合回归、经授权启用，再核对进程指纹和真实请求证据。

## 来源模块与实际发送卡片

39个来源模块始终连续展示；空模块和关闭模块没有正文也不额外注入。黑话、词条、绰号由各自C层拥有源按已确认状态、来源、条数上限筛选。O层显示当前预计与当时采集的筛选统计；旧记录缺少实际证据时标为未知，不把库总量当作注入量。

- 系统设定与角色要求：1号角色设定和DSH自身系统规则。
- 用户消息与附加资料：本轮背景：2–35、37、38号有效内容，以及36号的收件状态。
- 用户消息与附加资料：本轮任务和新消息：39号任务说明，以及36号中按seq去重的新增聊天原文。

36号保留一个编号和一个关联开关，内部拆成收件状态、新增聊天原文。39号整体发送。来源模块表示内容来自哪里；上述三张卡片表示最终如何组合发送。

工具清单位于请求摘要旁，列出所选请求中可用工具的用途和参数。AI历史消息可含实际发起的调用，并不都已发给QQ用户；工具返回结果显示对应调用ID的数据或错误。当前请求对比上一次，上一次对比初始；初始作为固定基线。

动态资料按桥接批次更新快照，不在每次模型请求前重新读取心情、记忆、词条或黑话。工具修改后，后续请求首先通过工具返回结果看到新值；旧快照可能同时存在，直到新一批上下文到来。工具调用与返回按原请求顺序合并展示，并保留调用ID；它们仍属于消息历史。

## 三个消息窗口的归属

最近消息保留上限recentLimit是本地回查缓存；未读队列保留上限unreadLimit是尚待处理的队列。两者经单次快照条数/字符预算筛选后，聊天原文统一进入默认36号的新增聊天原文部分；收件数量/进度进入36号收件状态。原文统一标记为【新增 QQ 消息数据】，当前没有逐条区分近期缓存来源和待处理队列来源的统一标签。11号另以【此刻状态】概括未读数和最近来信，不重复原文。

contextWindow当前主要筛选12号记忆模块下【当前小上下文窗口内对用户的行为印象】，根据最近N条中的实际发言者和印象更新时间筛选；它不是整个模型请求的消息条数上限，也不清除已经进入DSH的聊天历史。
