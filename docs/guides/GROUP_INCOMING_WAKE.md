# 群聊会话开启、持续与结束

私聊来信100%进入唤醒与回复流程，不抽签、不使用群聊触发条件。独立额度、权限、暂停及明确免打扰仍生效；不能用概率默默忽略私聊消息。

## 群聊循环

1. 尚未开启会话：当前静默阶段递增主动概率p，加上本条命中的最大唤醒加成q，按min(1,p+q)判定一次。@（含引用bot）、管理员名字、向bot提问、拍bot有各自加成，多命中取最大值。例：p=20%，@加50%、名字加30%，同时命中最终70%；未命中时q=0，仍可按p开启会话。
2. 唤醒成功：在处理、回复和等待期间，后续来信不再逐条抽签。与私聊共用消息读取、回复、发送频率、额度和等待窗口；不绕过这些限制。
3. 等待判定endRound=true：本轮会话立即关闭，停止追加追问或新话题；不必等待DSH取消回执才关闭入站状态。之后恢复递增主动模型，仍按最近实际互动时间与静默配置计算下一次机会。

桥接只暴露conversationAwake事实：已入队/已启动且未取消、未被等待判定关闭的回合。不能用宽泛的“繁忙”替代这个事实。概率及匹配由life-wake-reasons组件唯一决定。

## 设置归属

- 生命周期组件：群聊四类唤醒加成、管理员名字、群聊唤醒频率。加成字段groupAtBonus等只有一份配置；0只取消该项加成。
- 发送与等待：阶段初始概率、增速、检验间隔、心情与意愿、最大静默兜底，以及已开启会话的等待结束概率。
- 来信、实际日程/冒泡等发送会重置静默阶段；日程、监控及其他独立通知保留各自投递规则。

名字只匹配管理员字段；短英文按词边界，不把引用原文或@其他人的昵称当作名字命中。提问必须面向bot，不把所有问号当成提问bot。事件结果保留最近128条，重复事件不再次抽签；已经接纳的消息仍按收件/回复凭据防重。
