# 群聊来信与静默主动的统一概率

每条群聊来信先读取重置前的静默阶段有效概率 p，再从被 @（含引用 bot）、管理员填写名字、向 bot 提问、拍 bot 中取最大的 q，以 min(1,p+max(q)) 立即判定一次。没有命中则 q=0。例：p=20%、@=50%、名字=30%，最终70%，不累加多个 q。

- L 层“生命周期组件 → 来信唤醒偏好（仅群聊）”：四个 q、名字、补充表达偏好和群聊唤醒频率。
- L 层“发送与等待 → 什么时候主动”：静默阶段、基础概率及增速、检验间隔、意愿和宵禁。p 受当前心情与聊天意愿缩放。
- 四个 q 的初始值依次为0.6、0.4、0.3、0.6。0只取消该项加成，不取消基础 p。名字从原管理员关键词迁入，可使用逗号、中文逗号或换行；短英文按词边界匹配。只匹配用户原始文字，不把引用原文或@其他人后渲染出的昵称当作名字命中。提问识别使用管理员名字、@事实或面向“你/您”的问句，不硬编旧角色名。

来信随后重置静默阶段，页面分别展示“当前基础概率”和“最近来信判定”，因此两者可能不同。重复传入同一事件沿用记录，不再次抽签。最近128条来信判定按时间保存到组件状态，插件重载仍保留。第一条消息、第一条拍一拍也不能绕过概率。

私聊不抽签；限制允许时，每条进入回复处理。概率通过表示进入处理流程，不等于保证发送。预算、专业问答额度、免打扰、暂停、权限和实际发送限制继续生效。独立日程、通知和主动调度保留原投递规则。

“等待无人回复后结束本轮”的概率是另一件事：它决定何时停止当前等待链，不决定群聊来信是否唤醒，也不会替代静默主动模型。

## 单一拥有源

数学、名字与提问匹配：plugins/qq-components/life-wake-reasons/group-wake.mjs。
阶段、心情和意愿、事件判定记录：同组件 proactive.mjs 与 proactive-policy.mjs。
桥接只提取事件事实，在 observe 重置静默前调用 proactive.incoming，并在配额入口与唤醒入口复用结果。AI 的 qq_set_wake_config 不再暴露或接受 triggers/active 固定概率覆盖。

L0与L1共用插件声明，按字段渲染；提交前重新读取最新配置，仅合并当前分区字段，避免两个页面互相覆盖。一次性迁移位于src/migrations/group-wake.mjs：先备份原配置与指纹，恢复旧管理员名字、关闭项映射为q=0、保留显式新参数，删除旧全局推荐触发字段。重启后清理会话的旧triggers，保留明确约定的定时唤醒。

启用涉及桥接核心和MCP工具说明，需要受控加载；源码与隔离测试通过不代表正在运行的进程已更新。
