审计开始时配置为 Pro+high。保留账本按 (session, turn, step, retry) 去重后的样本中：Flash 1904 步，Pro 720 步，另有未标记模型样本。最高单步输入（含缓存命中）约67万 token。它不是账户全量账单，也不是单独的用户消息数。reasoning 桶为0不能证明没有内部推理。

因此额度消耗同时受模型误升档、维护调用、工具循环和不断增长的历史上下文影响。这里没有凭未核实单价计算费用，也没有承诺固定节省百分比。连接已正常时不再靠模型反复修桥接；日常健康检查本身不调用模型。

## 统一调度与语义时间约定

life-scheduler 统一业务时钟和任务注册/撤销。业务概率逻辑仍由相关组件判断；网络超时、重连和协议租约保留在环境层。停用调度中心会暂停定时业务，普通收发仍工作。

life-user-availability 使用现有 qq_memory_append 传结构化约定，不新增 MCP 工具：免打扰的起止时间、每日时段、稍后联系或取消。模糊时刻先补问，“现在没空”不猜结束时间。确认语“好的，谢谢”不会解除免打扰；翻译/引用/转述不触发任务变更。

改期、取消与提前回来撤销旧 ID；这个 ID 随繁忙/离线队列保留，实际投递前再验证。任务与变更状态保存在插件状态文件，发送凭据独立保存。过期、已取消或已执行任务不自动重放；没有结束时间的免打扰结束由用户回来触发。

日记当天同会话一次，不自动追发昨天日记；工作报告可以补生成文件，但不补推旧报告。校园通知按每个来源 ID 去重，而不是仅按可变的整批文本。脚本保留其另一工作线的课程策略和 DOM 改进，仅统一通知出口。当前旧核心尚无新通知 API 时，使用相同凭据与既有合法鉴权接口兼容，不反复重启。

出站会再次检查暂停、免打扰和有效期。发送前 claim，成功记 sent，未知记 uncertain；后两种未核实状态不自动重发。网络端不提供严格 exactly-once，已经开始发送的消息无法撤回。遗留凭据锁不自动抢占，需要独占维护时由机主核实恢复。
