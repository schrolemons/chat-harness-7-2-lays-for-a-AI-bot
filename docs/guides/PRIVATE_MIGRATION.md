# 私人部署与原始会话迁移

> 本页是独立的 legacy 快照恢复流程，需要明确授权且仅用于确实要恢复历史的新目标。现有私人 bot 的 managed 插件迁移不运行 restore、不替换 source/state/roles/旧会话；请使用 [独立实例安装与精确迁移](../INSTANCE_INSTALLATION.md) 的精确候选和停止写入窗口。

私人仓库保存本人的角色卡、资料库及 `private-data/` 快照；公开发行包不含这些资料。两者使用同一套功能代码，只有个人内容与中性默认内容不同。

## 快照包含什么

- bot配置、白名单、人物档案、会话记忆、日记、日程、事务、组件状态及发送凭据。
- 本工程所属的 DSH v4 原始会话：保留会话 ID、事件 seq、聊天与工具调用/返回、来源关系；读取全部串联的 Zstandard 帧，不只保存第一帧。
- 被这些会话引用、且内容哈希核验通过的 DSH 附件对象。
- 角色与私人资料库直接在私人源码树中版本管理，不重复复制到快照。

密码、API密钥、访问令牌、Cookie和登录数据库不上传。历史中出现的凭据也会脱敏，工具定义中名为 `token` 的字段结构保留。原始事件之外的缓存、无关工程会话及浏览器登录状态不备份。

## 新电脑恢复

1. 安装 Node.js 24+、DSH、QQ和SnowLuma；启动DSH一次完成初始化及自己的模型服务登录。恢复原始历史时，先关闭目标机器上的DSH，避免与正在运行的会话写入竞争。
2. 克隆自己的私人仓库，运行 `npm ci`。不要从公开仓库寻找个人资料。
3. 先预览，再恢复：

```powershell
npm run restore:private
npm run restore:private -- --apply
```

使用独立 DSH home 时，在两个命令后都增加 `--dsh-home D:/YourDSHHome`。恢复器会校验每个快照文件的SHA-256、路径和原始会话头，调整工程根目录与DSH home路径，再按DSH v4编码恢复会话目录。保留原始会话ID，因此桥接原有会话映射继续有效，不通过创建空会话冒充历史恢复。

4. 插件注册按 [独立实例安装与精确迁移](../INSTANCE_INSTALLATION.md) 单独准备、审查和应用候选。旧命令 `npm run setup -- --profile desktop` 不再用于 managed 统一插件注册。完成显式恢复与安装后，再自行打开原 DSH，核对自己的账号和允许目标。
5. 运行 `npm run doctor`、`node scripts/bridge-health.mjs --json`，查看原私聊/群聊的历史和日程。旧的待发任务仍遵循有效期、撤销和发送凭据守卫，不会因为恢复而自动重放未知结果。

安装 bootstrap 不会自动恢复随包携带的私人快照；已有配置始终保留。需要独立恢复时，先使用上述预览并确认目标，不能把插件迁移当作快照恢复授权。

## 已有数据与本机依赖

恢复器默认拒绝覆盖内容不同的业务文件，且始终拒绝覆盖不同的原始会话日志。重复恢复相同快照是幂等的。本机已有凭据会保留，空缺凭据需要重新登录或配置，不能把脱敏占位符当作有效密钥。

确需覆盖经过人工核对的业务数据时才使用 `--overwrite --apply`，原文件先备份；这不会允许覆盖冲突的DSH会话。软件安装位置、外部音频库和自建脚本若不在工程内，需要在新电脑安装或通过控制台改成目标路径；它们不是Git能复制的登录状态或系统环境。

## 更新私人快照

`npm run snapshot:private` 生成带采集时间、文件哈希及排除项的快照。源码、角色和该快照一起提交到指定私人仓库；保持仓库为private。业务文件与会话日志逐文件稳定读取，因此快照表示记录的采集时刻，不会持续实时同步运行变化。公开发布必须从独立导出目录构建，禁止将私人快照作为公开附件。
