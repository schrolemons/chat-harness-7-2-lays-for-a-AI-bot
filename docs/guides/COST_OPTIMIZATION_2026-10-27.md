# AI助手费用排查与优化（2026-10-27）

## 核实的原因

从本机保留的 52 条桥接相关 DSH 会话原始日志复算，而非累加控制台快照。计价按调用当时的模型、北京时间峰谷与当前官方单价。覆盖现有/已退役主会话、任务会话与摘要生成；不是平台账单，不包含已删除或未保留日志、其他 API 客户端及未返回 usage 的失败请求。

10-27 为当天未结束的部分数据，详见 `state/cost-audit.json`。完整原始日志发现单次输入最高 727,469 token；10-26 的输入中位数 370,296 token。10-26 共 295 个回合、2894 次模型请求，一轮平均近十次请求。

1. **上下文保留过大。** 原预设没有显式压缩预算，沿用约 80% 上下文容量才触发的默认值；模型窗口为 1,000,000 token，默认输出预留与 headroom 又将实际触发点限制到约 678,464 token。工具执行、等待、发送和下一步判断均重新读取这些历史。缓存命中仍收费。
2. **Pro 的自动升级。** `obs-cost-policy` 根据“工作词+复杂词”自动升级，开发/排障很容易触发。10-26 Pro 占估算费用约 75.5%。如果该日保持完全相同 token、仅将全部模型换成 Flash，回算约 60.39 元；这是历史反事实比较，不是优化后账单，也不等于降档后的质量保证。
3. **工具调用较多。** 后台 QQ 社交以及 owner 开发工作均有消耗；不能把所有请求当成普通聊天，也不能只根据最终回复长度估算花费。内部维护并不是现有记录里的主要费用来源。
4. **原控制台费用口径不可靠。** 基线把整条会话累计 token 按最新模型/基线时刻重新估价，跨模型与跨峰谷历史会失真；逐轮保留窗口也不完整。实测总额会小于逐轮归属额。此次提供独立原始日志核算，未把该控制台金额当平台已扣费，也未修改运行中账本核心代码。

- 四套预设生成并通过 DSH 原生接口热加载，`agentPresets/read` 已逐套回读确认，`application=applied` 且无 warnings。

| 场景 | 自动压缩阈值 | 最近原文保留预算 | 摘要模型 / 输出上限 |

| qq-chat / qq-chat-v2 | 120,000 token | 24,000 token | Flash / 4096 token |

阈值按当前模型的 1,000,000 token 窗口换算；近期原文按完整消息/工具对选取，非严格截断上限。headroom 为 8192，最多一次额外压缩/溢出恢复。单条旧工具输出超过 16,000 字符时保留头 12,000、尾 2,000 字符；原始日志保留，模型可按需重读完整结果。压缩摘要会丢失部分逐字细节，不承诺聊天质量完全无变化。

**运行边界：** DSH 已存在的 Agent 保留原预设版本，新预算在新建/重新恢复到新预设版本的 Agent 上生效；定义热加载不等于现有 Agent 已迁移。本次没有重启 bridge 或 DSH，没有取消正在工作的 owner 会话，也没有重置任何会话。

旧会话的一次原生 `/compact` 已成功：377 个历史条目、约 198,518 token 被摘要替代，原始事件保留。另一条因上游 `DeepSeek Messages transport failed` 未完成，owner 正忙时被原生闸门拒绝；随后停止批量尝试，正在发起的下一次请求已取消并在日志中结束，没有留下压缩锁。没有为验证而发送 QQ 消息。成功压缩后投影可能仍显示上次请求压力值，要等后续真实请求刷新，不能将旧投影冒充优化后的实测输入。
