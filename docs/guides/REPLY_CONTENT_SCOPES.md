# 完整内容拆分、普通聊天限频与任务豁免

`ctx-chat-reply-shape` 按用户的一份完整语义内容累计拆分条数。`maxMessagesNormal`、`maxMessagesCasual`、`maxMessagesSerious` 保留原配置键，分别表示普通、轻松、严肃内容最多拆成几条，默认均为3。上限不要求发满。

一份内容可由多条用户碎片消息合并。例如“我今天去吃饭”“是在学校食堂”“那个菜挺好吃”可以共同表达同一个完整意思。相反，同一个等待窗口收到的三份独立含义分别拥有内容额度；每份上限为3时，可分别发3条，合计3+3+3=9条。没有额外的等待批次、原生回合或模型请求总条数门槛；普通聊天分钟/小时限频仍独立校验。

内容必须对应实际准入的用户来信。按完整含义分组，不按QQ消息数或LLM调用次数发放额度。同一内容跨模型请求、读取、等待、换发送工具仍共用原计数；重复声明、重读旧消息不能续领，已开始发送后不能靠重新划分含义增加额度。文字、引用、图片、语音、表情、拍一拍和文件共用所选内容的真实物理发送计数。

## 普通聊天的动态限频

心情表示 bot 的主观感受，聊天意愿表示用户客观忙闲与精力。两者通过 `engagementFactors` 的系数F缩放普通聊天的分钟、小时基础频次，不缩减每份内容的拆分上限。它们对主动概率、回复深度及心情风格的既有职责保留。

心情启用且两项分数有效时：

`F = (0.2 + 0.8 × 心情/100) × (0.2 + 0.8 × 聊天意愿/100)`

分钟和小时窗口分别计算。基础值大于0时，有效额度为 `max(1, ceil(基础额度 × F))`，基础值为0时该窗口始终不限。例如两项均为50时F为0.36，基础8点/分钟变为3点/分钟，基础60点/小时变为22点/小时。每份普通聊天语义组在首次发送时占1点。文字与媒体共用该点，同时逐条累计到原配置的拆分上限。新组没有可用点数时，整个回复暂缓。任务接手共享这两个时间窗口，也按整组1点计算。

费用预算属于 `life-token-budget`。普通聊天新组在费用耗尽时暂缓，思考提示、超时道歉和机械预算补话仍受费用约束。费用检查通过且第一条确认送达后，同一会话的当前回合可在原拆分上限内完成同组投递。实际模型费用照常记账。

## 任务组1点接手、执行续权与回执

以下工作把同一任务及其完成汇报作为一组：接手时在共享分钟/小时额度中占1点，组内实际执行与汇报发送不重复扣点，也不受每份普通内容拆分条数限制。

- 用户明确授权的任务执行。
- 传话，无论规则组件执行还是模型执行。
- 日程创建、修改、取消及真实到期提醒。
- 报告查看、检索、摘要及任务完成汇报。

开始任务仍须通过原有唤醒、适用费用检查和弱限频：费用冷漠阶段私聊默认每5条唯一来信触发，群聊按配置间隔触发；未到允许时机不能凭任务标签另开调用。还须在共享分钟/小时窗口取得任务组1点接手额度，同一组只成功扣除一次。通过检查后持久保存只绑定该任务的准入权限。已准入任务若在执行中跨过费用软阈值或硬上限，可以继续完成该任务并及时汇报，不因执行中超限被截断。全部真实调用费用仍计入会话账本和全局总额。

没有可用接手额度时，保留来源消息为已读未处理，不标成已回复或已完成。额度恢复后自动重新核验费用、唤醒、弱限频、权限和时效等开始条件，成功占用1点后再执行；同任务续跑、换请求、重读或重载不重复扣点。持久任务接手记录独立于实际QQ投递收据：接手只表示该组已获得执行资格，不能冒充QQ发送成功。组内真实发送仍逐项登记成功、确定失败或未知结果。

执行续权只覆盖原任务范围及其必要结果汇报，不授予无限新任务或无关聊天的调用权限。普通聊天写“这是任务”、模型自报任务身份、更换工具或重读旧消息，都不能自行铸造准入权限或新建已付点任务组。日程操作和真实到期提醒同样须具有可验证的原任务来源；任务组接手1点、组内不重复扣点及不限拆分的规则，优先于旧定时突发额外条数配额。普通时间冒泡等闲聊不会仅因定时发生而变为任务。

豁免不取消模式、权限、白名单、跨会话目标与媒体授权、免打扰、暂停、时效、维护回合禁发、防重或持久发送凭据。实际发送前仍复查这些守卫；仅实际成功回执可标记送达，确定失败才释放预占，未知结果保留，不伪造成功或自动重发。

配置拥有源为组件 `plugin.json`，控制台拥有源为 `console/layers/L/`；该指南描述规则，不构成保存配置、热加载、重启、部署或真实QQ投递的完成证据。
