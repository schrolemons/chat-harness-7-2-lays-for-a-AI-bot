## 本次改动

1. 增加唯一的只读健康入口：管理端工具 `mcp__bridge-health__bridge_health({})`，本机命令 `node scripts/bridge-health.mjs --json`。O 层插件 `obs-bridge-health` 已热加载。
2. 工具区分 ready、auth_required、unknown、DSH 不可用、QQ 断开/账号离线、上游退化、心跳过期。只返回组件状态，不返回原状态接口中的聊天活动、号码或凭据。未知不能当作掉线。
3. 日常检查不会创建测试会话或调用模型；它不验证模型余额、额度或每项业务任务的成功。模型错误与连接故障分别处理。
4. 诊断鉴权与真实 bridge 保持一致：合法的手动 `config.consoleToken` 优先，其次持久化 token；不拿旧 token 覆盖手动 token。重定向不跟随，返回内容异常报告 unknown，不谎报网络不可达。
5. `--check` 只读；普通启动遇到健康实例立即结束，不扫描端口、不重复启动。缺少完整状态/鉴权失败不杀已启动进程；`--once` 退出不自动重拉；端口恢复只保留一个重拉入口，并防止巡检并发重叠。
6. DSH 诊断脚本统一按显式参数 → 环境设置 → 当前 config.json 解析地址；只有无配置时兼容 Web 默认 3080。配置损坏明确报错，不静默退回旧端口。
7. 自查插件、环境插件说明、AGENTS.md 和 README 统一规则：ready 停止修连接；旧日志、401/403、空闲不能证明掉线；插件优先热加载，重启必须等机主同意。受限 QQ 会话没有诊断工具时，报告无法核实，不尝试提权或改接口。

## AI助手以后怎么查

优先使用管理端工具；命令行入口：

```powershell
node scripts/bridge-health.mjs --json
```

看到 ready 就停止连接修复；业务任务出错则查对应任务。auth_required 先核对诊断鉴权，unknown 先补证据。不要把 `src/self-test.js` 当日常检查，它会新建会话并调用模型；不要用 `--force` 或重复重启试错。
