# 插件运行、统一调度与验收约定

## 插拔边界

插件为可信本地代码，不是恶意代码沙箱。业务组件通过受控能力访问 QQ/DSH，不模拟登录、绕过平台校验或转发凭据。

目录为 `plugins/qq-components/<id>` 或 `plugins/qq-components-user/<id>`，包含 plugin.json、index.js 和 skill.md。ID/工具冲突拒绝覆盖，错误组件不阻止相邻组件。

启停和配置保存仅重新加载目标组件。停用后钩子、服务、工具、旧能力和待投递请求撤销；旧实例不能重新注册工具。异步导入、工厂和 dispose 有超时，Promise 拒绝隔离。同进程机制不能中断恶意同步死循环。

beforePrompt、relayIncoming、wakeTail 是同步协议。异步工作放在 onTick、工具或服务，使用 ctx.signal 与 ctx.isActive 合作取消。ctx.runtime 保存同进程重载状态；跨进程状态存 ctx.state，采用原子写入。

## 配置与观测

管理 API：GET /api/plugins、GET /api/plugins/detail?id=...；POST /api/plugins/toggle、/config、/reload。管理接口需要控制台鉴权，智能体不能借会话令牌修改管理配置。

配置覆盖存 `state/plugins/config/<id>.json`，验证字段名、类型及声明的范围。管理页显示实际钩子、服务、工具、调用和异常计数。“加载成功”不等于功能验收。

声明型插件只提供说明和查询，不表示它能修改底层传输或沙箱。独立 MCP 入口也须检查启停，不能只隐藏管理页里的工具。

## 调度、语义与中期记忆

业务强制定时入口统一注册到 life-scheduler。追问概率、话题判断等留在业务组件中。中心停用时暂停定时业务，普通传输继续；网络超时、重连和协议租约仍属于环境层。

life-user-availability 把用户的免打扰和稍后联系约定保存为结构化计划。改期、取消或提前回来会撤销旧任务 ID，排队后在实际投递前仍检查 ID。含糊的“晚上”先补问具体时间；没有结束时间的“现在没空”不猜时间。

计划、变更和执行状态跨重启保存；发送凭据独立于聊天上下文及组件热重载。中期笔记保留已发送通知的 ID、时间和简短主题。自动发送前查确定性凭据，不能只依赖模型记忆。

日记当日同会话只发送一次，人工点播与定时入口共用凭据，不自动追发昨天日记。工作报告可补生成文件，旧报告不补推。校园通知按单个来源 ID 去重，不因组合文本变化重发旧项目；过期记录不重放。

发送前持久化 claim，成功后记 sent；结果不确定记 uncertain。sent、claimed、uncertain 均不自动重发。网络无法提供严格 exactly-once，本系统选择未知时待核实，避免重复发送。已经进入网络发送的消息无法撤回。

## 验收

1. 检查实际入口、配置、钩子、工具和服务。
2. 用真实工厂验证典型 payload 对实际输出的影响。
3. 逐个停用、全部停用，验证相邻组件和普通传输仍可运行。
4. 验证配置、排序、连续重载、旧工具撤销及队列撤销。
5. 覆盖繁忙、离线、暂停、免打扰、改期、取消、过期和跨重启防重。

运行 `npm run test:plugin-audit`，在临时副本执行离线回归，结果保存在 `state/plugin-audit-regressions.json`。模拟测试不能冒充真实 QQ 或模型验收。

本次 src/bridge.js 和 src/plugin-host.js 的修改需要重启桥接才生效。按 AGENTS.md，先说明影响并等待机主明确同意；不需要为此重启 DSH。
