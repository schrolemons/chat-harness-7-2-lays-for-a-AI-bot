# 管理员环境与二代派生预设

## 权限规则

owner 只标识谁可以使用管理员私聊入口，不单独授予管理能力。QQ 高权限调用统一要求：

1. 主动启用 `socialV2.adminDev.enabled`。
2. 所选预设存在且可用，并提供高权限能力；`qq-chat`、`qq-chat-v2`、`qq-learning`、`campus-summary` 不授予管理权限。
3. 当前 owner 私聊实际装配的预设与所选值相符；旧会话、旧令牌和伪造请求字段不放行。选择不存在的预设时不得静默回退。

封闭 Agent 同样遵守开关。管理工具、独立任务、跨会话资料读取、文件发送、工具审批、配额豁免都使用同一授权来源。环境关闭或预设变更后，旧聊天映射退役、后续调用拒绝，未完成的委派任务取消；历史与产物保留。原生 DSH 工具和任务工作会话还在每次调用前检查配置及会话映射。

控制台操作者令牌保持独立。QQ 会话不能通过控制台配置接口自行开启环境、修改安全设置或调用服务重启接口；生图密钥配置等继续仅控制台可用。完整 DSH 工具能力仍遵守 DSH 沙箱、操作系统和审批策略，不等于自动提权或取消审批。

原生 DSH 子代理只沿运行时注册表中真实、仍可查询的 `origin=subagent` 父链继承授权，不接受调用参数提供的父会话声明；循环、缺失父节点和失效根映射一律拒绝。每次工具调用仍重新读取管理员开关和所选预设，因此关闭开关后后代不会保留权限。首次使用无需先创建桥接任务文件。

控制台保存或还原共享聊天预设时，同时生成派生管理员预设和根 `cordis.patch.yml` 安装组合包；源码、嵌套补丁和根组合包使用同一生成路径。

## 一个聊天源，加一份权限扩展

`qq-admin = qq-chat-v2 的共同聊天配置 + 管理员能力扩展`。

- 共同聊天与机制源：`dsh/agent-presets/qq-chat-v2/agent.cordis.yml`。
- 权限扩展源：`dsh/agent-presets/qq-admin/agent.cordis.yml`，仅维护管理员权限声明及新增 DSH 能力；不复制聊天流程或维护第二份人设。
- 生成器：`scripts/build-agent-preset-patches.mjs`。构建 `qq-admin` 时先读取完整二代配置，移除普通聊天工具限制，追加 DSH 执行能力及授权检查。共同的 ask/todo、压缩、上下文编排以及未来新增共同模块均直接继承二代源；联网能力差异属于权限扩展。
- 聊天提示词从二代的共享工具协议段直接派生，不另写管理员聊天口吻。该协议段的结构标记属于生成契约；破坏结构时构建拒绝，不能静默留下旧管理员规则。
- 人设仍由桥接读取同一份角色卡并注入；共享组件引用同一实现。更换人设或更新组件时不需要改第二份管理员预设。内置二代与管理员预设的权限不同，收发、等待、潜水、人设和共同上下文规则相同。

自定义 DSH 预设保留用户自身的工具和指令。若希望严格保证与二代的聊天体验一致，应选择项目提供的 `qq-admin`；任意自建预设的提示词内容无法被项目保证。

## 更新和同步

- 在 Console 保存或还原二代仿真提示词，会重建二代和管理员的实际 bundle 文件。保存失败会回滚；先校验全部派生内容，再写产物，避免一份更新一份停留旧版。
- `npm run build:console` 和 DSH 安装配置流程会自动生成派生预设。
- 手动修改共同源文件后，可运行 `npm run build:presets`；不要手改 `plugins/qq-agent-presets/presets/*.patch.yml`。
- `npm run check:presets` 检查产物漂移及共同规则一致性。测试会模拟未来修改提示词、压缩参数、共同工具参数与新增共同模块，验证管理员预设自动跟随，且不会因扩展文件保留旧值。
- `npm run test:admin-permissions` 验证开关、预设、实际会话及原生执行边界。发布或交付其他管理员前执行这两项检查。

磁盘同步与运行中装配是两回事：角色卡和共享组件按原有热更新机制处理；DSH 已装配的预设需重载或完整重启 DSH，桥接核心鉴权修改需重启桥接。未重载时不能宣称新权限已经生效。不得为验证擅自重启服务。

## 验收范围

隔离测试覆盖所有当前注册的管理工具（包括高风险操作的执行替身）、关闭与开启两种状态、非 owner、群聊、旧会话、降权预设、撤权和任务生命周期。真实 QQ 验收使用授权的 owner 会话，只读探针和无害执行验证工具可用性；服务重启及破坏性执行由隔离测试验证关卡，不把模拟结果当真实执行成功。
