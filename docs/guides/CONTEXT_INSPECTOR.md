# 上下文检查器的记录口径

本页读取冻结的模型请求证据，不调用模型或发送 QQ 消息。界面组件编号与消息序号、DSH 内部回合编号分别计数。

## 三个请求位置

初始请求是 Agent 从 idle 进入 running 后首次采集的模型请求。在一次持续运行中，即使来了新背景批次、进入下一 turn，也保留此基线；每次模型请求都滚动更新上一次和最新记录。Agent 回到 idle 后，再次进入 running 才建立新基线。

采集器以 `agent/status` 记录 `processingId`，将其与请求一起持久化。最多保留初始、上一次、最新三个位置；若两个位置指向同一个 requestId，界面合并成一个选项。缺失证据不补造：运行中途加载且找不到起始采集时，不把刚看到的请求伪称为初始请求，也不假造调用序号。

旧版记录没有 processingId，仍按原 nonce 背景批次读取，界面标为“旧采集批次”。网页刷新不会升级 DSH 已加载的预设采集器；本机需按授权流程重新加载 DSH，下一次真实处理后核验 observerVersion 5、layoutVersion 2 及 processingId。

## 消息、工具与动态资料

消息列表遵循请求中的原始顺序；system/user/assistant/tool 是消息角色，彩色用途标签另行显示。tools 是与消息列表并列的工具定义字段，其界面位置不等于服务商的模型内部编码顺序。

实际请求的“组件来源”提供按名称定位固定编号、编号搜索及 05 心情、12 记忆与临时画像、25 日程快捷入口。目录位置不保证该次请求一定有正文；分别显示已携带、未提供、未采集或证据不完整。

新版把当前心情、形态与完整风格示范放进动态资料，不再改动系统角色卡。心情行为规则、会话背景与协议位于稳定 user 资料前缀；DSH 硬规则和角色原文在 system。系统固定说明当前管理员风格用于表达，不改变身份、权限或安全边界。

每次请求前从桥接组件拥有源刷新状态；变化才在历史末尾追加，撤回也有明确记录。历史快照保留在原位置，不能解释为当前值。05、12、25 的组件入口可以直接定位当前有效的消息位置。工具返回在前、变化后的组件状态在后；不改变配对，不把直接 QQ 测试发送当模型验收。memoryWrite 等后台场景跳过心情和日程时，原活跃状态会撤回。

实际请求提供结构筛选，筛选后的阅读编号连续，原始请求位置另列。tools 仍是独立字段。旧系统风格合并记录仅按当时实发显示，绝不追溯重写。缓存收益需在令牌账本核对真实命中，不能仅凭界面分区或字符估算宣称提高。
