# 上下文检查器的记录口径

本页读取冻结的模型请求证据，不调用模型或发送 QQ 消息。界面组件编号与消息序号、DSH 内部回合编号分别计数。

## 三个请求位置

初始请求是 Agent 从 idle 进入 running 后首次采集的模型请求。在一次持续运行中，即使来了新背景批次、进入下一 turn，也保留此基线；每次模型请求都滚动更新上一次和最新记录。Agent 回到 idle 后，再次进入 running 才建立新基线。

采集器以 `agent/status` 记录 `processingId`，将其与请求一起持久化。最多保留初始、上一次、最新三个位置；若两个位置指向同一个 requestId，界面合并成一个选项。缺失证据不补造：运行中途加载且找不到起始采集时，不把刚看到的请求伪称为初始请求，也不假造调用序号。

旧版记录没有 processingId，仍按原 nonce 背景批次读取，界面标为“旧采集批次”。网页刷新不会升级 DSH 已加载的预设采集器；本机需按授权流程重新加载 DSH，下一次真实处理后核验 observerVersion 7、layoutVersion 4 及 processingId。

## 消息、工具与动态资料

消息列表遵循请求中的原始顺序；system/user/assistant/tool 是消息角色，彩色用途标签另行显示。tools 是与消息列表并列的工具定义字段，其界面位置不等于服务商的模型内部编码顺序。

实际请求的“组件来源”提供按名称定位固定编号、编号搜索及 05 心情、12 记忆与临时画像、25 日程快捷入口。目录位置不保证该次请求一定有正文；分别显示已携带、未提供、未采集或证据不完整。

新版把当前心情、形态与完整风格示范放进动态资料，不再改动系统角色卡。心情行为规则、会话背景与协议位于稳定 user 资料前缀；DSH 硬规则和角色原文在 system。系统固定说明当前管理员风格用于表达，不改变身份、权限或安全边界。

每次请求前从桥接组件拥有源刷新状态；业务消息末尾只提供一份完整当前资料，旧状态只留原始日志。05、12、25的入口定位当前资料，不将历史状态反复发给模型。工具调用与结果保持原时间顺序；工具注册变化是DSH独立的协议记录，按原位置展示。后台场景未产出的组件不会沿用旧值，底层状态不会因此被删除。

实际请求提供结构筛选，筛选后的阅读编号连续，原始请求位置另列。tools 仍是独立字段。旧系统风格合并记录仅按当时实发显示，绝不追溯重写。缓存收益需在令牌账本核对真实命中，不能仅凭界面分区或字符估算宣称提高。

## 组件设置

设置按系统规则、稳定资料、动态资料分组，只能在同组内调整顺序。C01–C40 是来源编号，不是请求位置；C40 私人资料按适用会话提供目录导读，正文由读取工具按需获取。可视化 context 是管理设施，不作为发送或排序项；实际请求的组件来源统一显示40项，运行附加资料在原消息位置说明。旧版上下文精简功能及选项已移除，不再扫描或重写旧格式消息包。

## 记录来源与文字边界

QQ 原文按所选请求内可核对的双戳与成功回执，分为“QQ 历史消息”和“QQ 未处理消息”。已读但未完成仍属于未处理；complete/replied 和 bot 真实 QQ 消息属于历史。失败或跨会话回执不改变处理状态，状态缺失保留未知。只有编号和状态、没有正文的条目仍由 C36 管理，显示为其折叠的收件状态明细，不另设索引卡、不计入聊天条数，不用实时消息填补旧快照。

当前桥接任务独立说明目标会话、激活原因和任务要求，即使来信属于未处理窗口仍然保留。共同的回复协议放在稳定前缀，不随每个来信批次重复。`probability` 是群聊普通来信通过概率判定；处理已在运行时可接纳新批次，不代表每次都从空闲启动。

实际装填同样由 C36 提供唯一的当前收件索引。每次请求前只读刷新原窗口 seq 的 seenAt、repliedAt、receiptState 等字段，聊天正文保持原有增量接入与工具时间线，不借刷新索引接入新正文或写回已读。索引有编号不代表模型已收到该条正文，不能据此报告已读／已回复。历史工具回执保留在原执行位置，只用于回查当次执行结果。

聊天与工具历史采用单列时间线：QQ 消息、内部输出、工具调用及返回按采集位置穿插，不把所有 QQ 消息先排成一块，也不强行把记忆、印象、黑话工具挂在某条 QQ 消息上。聊天正文使用消息气泡，工具显示操作摘要与返回状态；展开可核对原始参数。工具配对使用 toolCallId，QQ 的关联跳转仅使用结构化 seq/messageId；没有明确引用时不虚构语义因果。失败回执不改变消息处理状态。原始请求顺序保留独立审计入口。

待处理区置顶本次桥接任务。旧快照没有独立任务槽位时，只将该快照最近一条有来源的桥接任务放在区首，并标明旧采集。工具回执里的用户引用原文单独显示来源，不补造收件 seq 或双戳状态；稳定前缀包裹的 QQ 原文仍会被解析，稳定资料不会被误当作整段任务。

内部输出分别展示“生成来源”和“数据流向”：最近输入或工具返回可定位到原始位置，但时间相邻不证明具体思考原因。普通 assistant 正文进入 DSH 会话记录；只有匹配发送工具的成功返回才确认 QQ 投递，sent=0、失败或缺少凭据均不确认。

原始收件 seq 始终作为入站消息的主要标识，不以从 1 开始的展示编号替换。新采集的 dialogueSeq 是同一会话中 bot 与用户共用的另一项对话序号，放在来源详情中；原 seq 继续用于双戳工具定位。旧 bot 记录若没有原始序号，明确说明缺失，不补造 seq。两个业务窗口按处理状态分组，各自内部排序；未处理消息可能比已处理消息更早，跨窗口排列不表示全局时间顺序。

旧版追加式请求的组件快照可以全部或部分被后续版本取代；历史证据仍按当时采集展示。新版请求只携带一份当前补充资料。停用/撤回仅停止沿用旧补充资料，不删除底层数据。模型内部输出与 QQ 发送回执分别显示。

工具定义新增/移除由 DSH 对比工具清单生成，记录 toolName；新增项的完整定义引用 request/header。只读查看会按消息ID从原生会话日志恢复事件序号、产生时间及工具名称，失败保留“证据未采集”，不推测。历史 user 输入若没有具体提交方，不冒充 QQ 发言；收尾提醒的历史格式识别会明确标注其证据边界。非文本占位说明是预览文字，不是模型收到的字面消息。

## 五段业务装填

界面统一使用“系统上下文、稳定用户上下文、聊天与工具历史、本次来信与处理任务、当前补充资料（历史后注入）”。可展开查看各层职责、更新方式及酒馆相近概念；这是概念对照，当前角色原文仍在 system，不伪造额外的世界书前后分区。组件来源与组件设置均提供职责说明，当前组件说明和所选请求当时正文分别标记，避免把新版机制强加给旧记录。

等待工具返回按“等待判定、下一步行动建议、返回的 QQ 消息”分段。只在工具名与调用 ID 可核对、返回 JSON 可解析时生成说明；缺字段不补造结果。结束概率是本次工具返回的记录值，静默判定不等于确认对方真实意图。C10 展示请求前的组件建议；超时后抽中的追问或新话题建议位于等待工具返回，归入工具历史，不冒充 C10 正文或 QQ 已发送消息。

QQ 原文按消息卡片显示，发送者、seq、当时回执与正文分开；完整消息字段可展开。结构化分段下方默认收起完整请求原文，便于核对而不重复铺满页面。新版当前资料说明与旧版追加快照分别显示，历史来源和原请求顺序不改写。
系统规则 → 稳定资料 → 原生聊天与工具历史 → 本次输入与处理任务 → 当前补充资料。后续工具调用与返回进入原生历史，下一次调用重新生成当前任务与资料；没有新增 QQ 输入时仍可保留桥接任务。业务视图按处理状态重新归类已有原文，不复制到实际请求。工具定义是独立 tools 字段，DSH 的工具清单变化协议事件另作解释。前后世界书、用户身份、角色与示例可以作为稳定区的细分类；资料位置不赋予其系统权限。
