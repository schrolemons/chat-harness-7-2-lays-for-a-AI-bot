# Bridge 传输恢复看门狗

守护进程每10秒读取本机桥接的 `/api/status`。控制台无法响应、DSH不可用、网关断开、账号离线、上游异常或心跳过期持续90秒后，只重启它自己启动的 bridge 子进程。检查周期使实际触发可能比90秒晚最多约10秒；桥接退出后仍由原有5秒守护重拉机制启动。

睡眠造成的长轮询间隔或时钟回拨会重新开始计时，不把睡眠时长当作恢复失败。健康但无人聊天不会触发重启；鉴权失败、证据不足、主动暂停和关闭模式也不会据此重启。

重启前先把次数写入 `state/bridge-recovery.json`，10分钟内最多两次，守护进程重新启动后仍保留该上限。记录损坏时停止自动重启，不能通过覆盖坏记录清空次数。正常重启优先请求桥接保存状态后退出；控制台无响应时才终止自己持有的子进程对象，不根据宽泛进程名杀进程。

本机制不重启QQ、SnowLuma或DSH，不读取QQ数据库、登录文件或聊天文件，不补取或重放离线历史，不新增客户端注入与协议探测。它依赖既有桥接状态，不能证明QQ客户端或平台已经许可AI bot，也不能保证没有风控风险。底层网关或客户端故障可能无法通过重启bridge解决；到达上限后保留现场并记录原因。

`config.json` 可设置 `bridgeRecovery.enabled`、`timeoutMs`（30000–900000，默认90000）及 `maxRestarts`（1–2，默认2）。关闭开关会在下一次巡检生效；修改时限或上限后需重新启动守护进程。验证使用 `node --test scripts/test-bridge-recovery-watchdog.mjs` 的隔离连接与子进程替身，不制造真实QQ故障或发送测试消息。
