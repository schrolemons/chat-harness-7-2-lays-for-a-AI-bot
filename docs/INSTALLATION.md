# 安装、更新与验收

## 安装顺序

1. 安装 Node.js 24+、QQ 和 DSH。首次打开 DSH 完成初始化和模型登录。
2. 自行下载 SnowLuma 完整发行包，在上游管理界面接入自己的 QQ，并开启本地 OneBot 端点。
3. `npm ci` 安装本仓库锁定依赖；兼容修补只处理本机安装的 npm 包导入扩展名。
4. `npm run configure` 新建自己的配置。默认仅允许管理员私聊，群列表为空。
5. `npm run setup -- --profile desktop` 安装预设、MCP、模式设置和桌面启动器；Codex 就绪时加 `--with-codex`。
6. `npm run doctor` 检查配置与链接；`npm start` 启动桥接，再用只读健康检查确认连接。

配置文件和 profile patch 包含本机绝对路径，这些路径在安装时生成，不是发布包预置的作者路径。不要移动已经安装的工程；如需迁移，保留自己的数据后在新位置重新运行安装器，核验所有目录链接。

## 验收范围

- 空白配置与依赖安装：`npm ci`。
- 文件闭包、无缺失 MCP、插件加载、临时 profile 安装幂等：`npm test`。
- 日程：过去事项默认隐藏；未来事项即使提前提醒过仍显示；重复事项展示下一期；历史查询保留原记录。
- 提示词与网页摘要：离线规则测试覆盖触发、去噪、缓存、失败回退和独立资料读取。
- 本机服务：`npm run doctor`、`node scripts/bridge-health.mjs --json`。

单元测试和模拟 profile 不会替你登录 QQ/DSH/Codex，也不能证明你的账号能调用所有外部服务。实际登录、OneBot 收发、模型调用和 Codex 咨询需要在自己的环境逐项验证。

## 常见问题

- **QQ 能连但缺预设**：检查 DSH 实际预设清单和 profile 的 `qq-agent-presets` 目录链接。重新运行安装器；不要回退到带本地工具的预设。
- **启动按钮红灯**：先读提示中的分项状态。没有设置 QQ 程序路径时，先手动打开并登录 QQ；不要反复启动多个网关。
- **没有 Codex 工具**：检查完整插件文件、自己的登录、可执行文件路径，以及安装时是否使用 `--with-codex`。
- **网页需要登录**：在本仓库独立 profile 中登录。日常浏览器已经登录，不代表独立 profile 也已登录。
- **没有校园/其他私人脚本**：这是有意排除的数据与定制代码，不是丢文件；在本地 `user-scripts/` 接入自己的适配器。

## 更新与卸载

更新代码前备份自己的配置和 `state/`；不覆盖账号数据，不复制别人的运行目录。安装器负责的区块保留其他 DSH 插件。卸载 Codex Peer 可使用其 `install.mjs --uninstall`；移除其他集成前先确认没有正在进行的会话，再从 profile 中移除对应管理区块和 bundle 声明。删除运行数据是另一项独立操作，请自己备份后决定。
