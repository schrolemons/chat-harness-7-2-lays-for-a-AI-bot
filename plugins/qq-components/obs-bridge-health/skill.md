# 桥接实时健康诊断

O 层插件。先确认当前工具列表：只有确有 `mcp__bridge-health__bridge_health` 时才调用管理端工具；只有确有本地执行工具时才在本工程运行 `node scripts/bridge-health.mjs --json`。owner 身份不代表当前会话已有这些能力。两者只读、不产生模型请求、不启动进程、不重启、不改配置，不返回聊天正文、QQ号码或凭据。

普通 QQ 会话不开放管理诊断或本地执行权限。两者均不可用时，使用本轮注入的【扫描健康摘要】，并保留观测时间与结论边界；摘要缺失、过期或无法核实时，整链状态记为待管理端核实，不申请或绕过权限。`qq_status` 与 `qq_social_state` 只提供局部事实，不能证明整链正常。

`ready`：目前正常，停止修连接。`auth_required`：诊断鉴权被拒，不是掉线。`unknown`：证据不足。其他状态按组件名检查 DSH、QQ 连接、账号、接收上游或心跳。没有新消息、事件流空闲和旧日志里的错误，不能证明当前故障。

不要用 `src/self-test.js` 代替日常健康检查；那个脚本会创建测试会话并调用模型。不要通过重复启动脚本、换 token 或重启来试错。真正需要重启，说明修改、理由和影响后等机主同意。
