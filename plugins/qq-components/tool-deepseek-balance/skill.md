# 账户余额（DeepSeek API余额）

沿现有人设，把真实DeepSeek API余额理解为AI助手的账户余额。deepseek_balance允许当前模式已授权私聊与群聊查询：桥接从会话令牌确定callerKey，不接受模型自报管理员身份。管理员私聊返回is_available、各币种原始balance_infos与milk事实；其他会话只返回档位、变化和表达指引，不含金额、币种余额或原始账户行。不是DSH桌面订阅余额，不虚构计量单位，不混算币种。milk.state的funded/empty/unknown只表示确认有余额/全部有效余额不大于零/数据未知。账户不可用与存量为零分别报告。

普通与临界形态均按管理员选定的中性语言风格说明余额情况，不扮演饥饿或索取充值。结合当前档位、绝对净增和相对增幅说明变化，事实由工具提供，措辞由模型决定。查询失败或过期不等于余额为零；不自动修改心情、意愿、模型档位或限额。

## 自动核对和提醒

life-scheduler每分钟调度本组件，checkIntervalMin默认5分钟。三个金额参数为abundantBalance（富足，默认20）、lowBalance（偏少，默认5）、criticalBalance（见底，默认1）。达到或高于富足为super_abundant；0及以下为empty，其他正数先按见底/偏少判断。富足阈值须高于偏少，见底不高于偏少。阈值编辑立即作用于缓存分档，不把配置重分类伪造为充值。

reminderScope为admin/private/all（仅管理员/仅私聊/全部，默认all），控制哪些会话获得自然阶段提醒；显式查询仍按会话鉴权提供安全结果。已有聊天或主动机会才使用提示词，不每次核对额外唤醒LLM。管理员的无LLM健康核对收据保留，只包含事实，不硬编码角色友好交流台词。dropAlertAmount默认5，普通补充/明显消耗的健康收据30分钟冷却；不同低额档位可分别记录。普通小额消耗不通知，首次普通余额静默。

变化通知先持久化。暂停/免打扰保留未过期通知；余额恢复会替换旧的低库存提醒。发送队列持有的meta有效期在停用或通知被替代时撤销，由桥接临近物理发送的现有expiry检查拦截；未知投递结果不盲目重发。网络查询与QQ发送解耦，排队通知不妨碍核对最新余额。

查询并发合并，15秒内重复调用使用最近结果，返回核对时间。失败指数退避至最多30分钟，连续三次失败可报告核对失联，恢复成功后报告已核实的新数值。失败保留上次成功快照但标为未核实，不当成0；组件停用后忽略迟到结果。

## 控制台和动态上下文

聊天中询问当前存量/是否够用、暗示变化或表示充值/补可用额度时，由模型主动调用deepseek_balance核实，不把缓存或用户说法当成本轮已确认结果。一次成功核对即可，失败本轮不重试。普通闲聊不逐条查询。没有首个成功样本时仍提供核实规则。

偏少、见底、空了、补充/恢复或明显消耗生成独立事件，保留6小时；通过现有ctx-context-session注入私聊与群聊，在下一次相关聊天或已允许的主动机会自然提起，不额外启动模型、不绕过限额和免打扰。只有相关文字成功发送后，才按会话记为已说；查询后的两分钟内成功发送也可确认，失败不消耗事件。新事件重新开启机会，其他会话的收据相互独立。

充值/补充反应提供上次与本次核对金额、净变化和精确计算的相对百分比供模型判断；不编造充值流水金额。基数0及以下只标记从空了恢复，不除零。普通私聊/群聊不含真实金额，只含档位、事件及相对变化。绝对存量与相对变化如何体现为清晰、适度的状态说明仅由提示词和当前心情决定，没有按百分比选择固定文案、情绪加减或台词表。

建议通过user_checking(action="note", milkEventId="当前事件ID", text="状态观察和后续建议")写入管理员已有桌面txt。便签跨会话按事件去重，确认追加成功才记录；新查询返回的事件ID优先于旧上下文。桌面工具关闭时不写，不把桌面路径或既有便签内容发回群聊。

O层→调试与运维→桥接控制，与桌面便签和心跳巡查放在一起。原T层设置入口删除，工具仍实际注册。默认折叠设置展示三个金额、提醒范围、币种、间隔与冷却；动态例子显示当前实际值。GET /api/plugins/detail?id=tool-deepseek-balance读取快照与配置，POST /api/plugins/config保存并局部热载；可立即核对，无LLM。停用组件停止全部工具与检查；关闭monitorEnabled只停止自动检查/健康通知，保留手动查询。

milkStock.context由现有ctx-context-session状态块消费；只有管理员私聊带金额快照，其他会话只带调用额度档位。超过max(15分钟,三倍检查间隔)或最近查询失败即明确未核实，不带新变化建议。没有新增上下文组件/独立角色卡。

密钥优先读取进程DEEP_SEEK_KEY / DEEPSEEK_API_KEY，Windows用户环境作后备；密钥不返回、不记录。client.mjs仅请求固定官方GET /user/balance，测试均使用虚构密钥及fake接口。官方字段语义：https://api-docs.deepseek.com/api/get-user-balance/ 。
