# API预算余额（DeepSeek API余额）

沿现有人设，把真实DeepSeek API余额理解为AI助手的API预算余额。deepseek_balance允许当前模式已授权私聊与群聊查询：桥接从会话令牌确定callerKey，不接受模型自报管理员身份。管理员私聊返回is_available、各币种原始balance_infos与milk事实；其他会话只返回档位、变化和表达指引，不含金额、币种余额或原始账户行。不是DSH桌面订阅余额，不换算未经核实的调用次数，不混算币种。milk.state的funded/empty/unknown只表示确认有余额/全部有效余额不大于零/数据未知。账户不可用与存量为零分别报告。

普通形态可以自然、轻轻说明实际限制与友好交流：偏少时惦记，见底时减少不必要调用，空了可表达想补充；确认补充后确认当前可用确认恢复可用。AI形态仍简明客观，尊重心情管理的双形态。按语境接话，不逐项播报字段、不每次用相同句式；需要向管理员报数时保留币种，不把旧快照当作刚充值。不自动修改心情、聊天意愿、额度或模型档位。查询失败和过期均不等于API预算空了。

## 自动核对和提醒

life-scheduler每分钟调度本组件，checkIntervalMin默认5分钟。三个金额参数为abundantBalance（富足，默认20）、lowBalance（偏少，默认5）、criticalBalance（见底，默认1）。达到或高于富足为super_abundant；0及以下为empty，其他正数先按见底/偏少判断。富足阈值须高于偏少，见底不高于偏少。阈值编辑立即作用于缓存分档，不把配置重分类伪造为充值。

reminderScope为admin/private/all（仅管理员/仅私聊/全部，默认all），仅控制哪些会话在已有聊天中获得自然阶段提示；显式查询仍按会话鉴权提供安全结果。独立告警仍只发管理员私聊，不广播其他会话。dropAlertAmount默认5，普通补充/明显消耗30分钟冷却；不同低额档位可分别触发。普通小额消耗不通知，首次普通余额静默。

有效告警按定时主动会话处理：组件通过requestScheduledConversation投递reason=milkStock，跳过主动概率抽签，由wakeTail提供核实事实，LLM依据当前人设、示范与心情生成一条短句，通过真实发送工具发出，不再走无LLM固定通知。发送计划硬限一条文字，同一事件不能靠读取新消息续领额度，不追加媒体或跨会话转发。只有真实QQ成功回执才标记sent、计入主动会话并重置主动模型的静默阶段与计时；受理模型请求仅为accepted。告警不是要求用户回答的问题，不产生心情组件的“无人回应”欠账。

变化事件在调用模型前持久化。暂停、免打扰、宵禁、预算/发送限额或会话忙碌时保留未过期事件，下次检查再尝试，不绕过现有限制；有效期2小时。余额变化会替换旧告警，组件停用/重载会撤销旧生成任务的发送资格，临近模型投递及物理发送都复查有效期。dispatching/accepted/uncertain跨重载不盲目重发，受理不冒充送达。网络查询与生成投递解耦，告警等待不妨碍核对最新余额。告警不附带无关待处理消息，也不授权批量标记它们的双戳。

查询并发合并，15秒内重复调用使用最近结果，返回核对时间。失败指数退避至最多30分钟，连续三次失败可报告核对失联，恢复成功后报告已核实的新数值。失败保留上次成功快照但标为未核实，不当成0；组件停用后忽略迟到结果。

每次成功查询（包括手动工具查询）都先更新同一份lastSuccess基准并比较变化；手动查询发现变化后立即后台尝试投递，不等下一分钟巡检，不阻塞余额返回或后续查询。普通自动变化先保存pending并按notificationCooldownMin合并等待，不能因冷却而丢掉事件；显式手动查询可立即反馈该已验证变化。低额跨档、归零和恢复仍立即尝试。普通小额消耗不增加告警。暂停、繁忙、免打扰或预算不允许时保留未过期事件。失败不会删除此前待发预警，但该预警须成功重新核实后才能发送；过期或已有未知投递结果仍不重放。

## 控制台和动态上下文

聊天中询问当前存量/是否够用、暗示变化或表示充值/补可用预算时，由模型主动调用deepseek_balance核实，不把缓存或用户说法当成本轮已确认结果。一次成功核对即可，失败本轮不重试。普通闲聊不逐条查询。没有首个成功样本时仍提供核实规则。

偏少、见底、空了、补充/恢复或明显消耗生成独立事件，保留6小时；通过现有ctx-context-session注入私聊与群聊，在下一次相关聊天或已允许的主动机会自然提起，不额外启动模型、不绕过限额和免打扰。只有相关文字成功发送后，才按会话记为已说；查询后的两分钟内成功发送也可确认，失败不消耗事件。新事件重新开启机会，其他会话的收据相互独立。

充值/补充反应提供上次与本次核对金额、净变化和精确计算的相对百分比供模型判断；不编造充值流水金额。基数0及以下只标记从空了恢复，不除零。普通私聊/群聊不含真实金额，只含档位、事件及相对变化。绝对存量与相对变化如何体现为自然、减少不必要调用、惊喜或确认当前可用仅由提示词和当前心情决定，没有按百分比选择固定文案、情绪加减或台词表。

建议通过user_checking(action="note", milkEventId="当前事件ID", text="自己的感受")写入管理员已有桌面txt。便签跨会话按事件去重，确认追加成功才记录；新查询返回的事件ID优先于旧上下文。桌面工具关闭时不写，不把桌面路径或既有便签内容发回群聊。

O层→调试与运维→桥接控制，与桌面便签和心跳巡查放在一起。原T层设置入口删除，工具仍实际注册。默认折叠设置展示三个金额、提醒范围、币种、间隔与冷却；动态例子显示当前实际值。GET /api/plugins/detail?id=tool-deepseek-balance读取快照与配置，POST /api/plugins/config保存并局部热载；可立即核对，无LLM。停用组件停止全部工具与检查；关闭monitorEnabled只停止自动检查/健康通知，保留手动查询。

milkStock.context由现有ctx-context-session状态块消费；只有管理员私聊带金额快照，其他会话只带API预算档位。超过max(15分钟,三倍检查间隔)或最近查询失败即明确未核实，不带新变化建议。没有新增上下文组件/独立角色卡。

密钥优先读取进程DEEP_SEEK_KEY / DEEPSEEK_API_KEY，Windows用户环境作后备；密钥不返回、不记录。client.mjs仅请求固定官方GET /user/balance，测试均使用虚构密钥及fake接口。官方字段语义：https://api-docs.deepseek.com/api/get-user-balance/ 。
