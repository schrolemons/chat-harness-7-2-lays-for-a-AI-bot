# 历史上下文与恢复回复

恢复时不把群聊旧消息当客服待答队列。群聊已缓存旧消息全部标记为仅作历史；私聊默认只保留最近5条未处理消息可答，`privateReplyLimit` 可在控制台填写，0表示全部只作历史。恢复之后的新来信不受这个旧消息窗口限制，进入正常优先处理。

`replyDisposition=history` 只取消自动待答资格，不写 `seenAt` 或 `repliedAt`，不代表QQ已读、不代表模型已读，也不代表已经物理发送了回复。真实双戳和异常审计继续保留；只有实际送给模型的正文才能产生已读证据，真正发送后才能产生回复证据。历史可以帮助理解当前问题，不应凭旧问题重新执行过时任务；现有独立任务和日程不因历史分类取消。

`historyLimit` 控制每次本地补取的上限，不删除原始记录；实际请求还受 C 层历史条数、消息快照字符预算和 DSH 压缩限制。`localHistoryEnabled` 只允许环境能力以只读 SQLite 连接查询当前机器人账号下 SnowLuma 自己的 `messages.db`，按白名单会话和数量过滤，不解密 QQ 原生数据库、不读取其他账号。历史补取不调用任何 QQ API、OneBot 历史 API、漫游接口或模型分类；失败降级为桥接已有缓存，不能声称拿到了完整离线历史。

历史回填不走普通来信处理器，不触发已读补话、群聊概率、画像抽取、媒体下载、即时唤醒或QQ发送。私聊待答候选仍经过本地配额决定，受限或含糊的旧请求只作上下文；未完成独立任务的状态保持原有归属。当前消息在历史补取完成后进入正常接收路径，避免因本地快照重复导入同一条消息。

恢复边界在首次恢复时固定并跨组件热加载保留；延迟导入只扩大本地缓存记录的历史候选集合，不把边界之后的实时新来信降为历史。双戳回查、会话待答计数和开机问候遵守这一资格；模型选择引用旧消息并真正发送后，允许为该条提交真实回复回执，不顺带盖掉其他历史消息。

统一资格：只有双戳回查窗口内明确标记 replyRequirement=required 的来信须按收件seq升序回应；普通群消息和未压缩历史为optional，可自由参与。未唤醒或无定向条件的群消息只作上下文。已读普通群消息可报告 context 与原因，不能借此跳过必答消息；不写 repliedAt。窗口外旧必答移为历史也不冒充已完成。消息详情缺失只读当前账号、白名单会话的本地缓存，禁止QQ消息详情、历史与漫游接口。

首条实际触发唤醒的消息固定为本次输入，不被稍后来信替换。初始回查窗口为空，后续回查包含首条中尚未回复的必答消息；普通自由消息不占窗口位置，也不挤掉已有必答。连续必答可合并，并允许绑定紧邻的后续普通补充，用一次真实发送为所答的多个seq提供回执凭据。未纳入回复的上下文不跟随盖章。自主概率增长、定时冒泡与日常自动唤醒时，历史是否回复由模型决定；私聊新消息默认必答，离线恢复旧私聊仍受privateReplyLimit限制。
