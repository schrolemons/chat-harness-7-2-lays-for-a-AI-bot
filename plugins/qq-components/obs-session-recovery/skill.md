# 群聊会话自动恢复

O 层组件，唯一拥有源为本目录。管理位置：桥接控制 → 群聊会话自动恢复。面板顶部只有一个插件启停开关；参数按钮保存全局判定规则，次数与冷却按群记录。没有向聊天模型注册重启工具。

## 判定

- 只接收当前映射群聊的实时 DSH 事件；启动历史快照不计数，重复序号不重复计数。
- 聊天回合连续出现同类、同错误文本摘要的确定性请求失败（400/422，INVALID_REQUEST、CONTEXT_WINDOW_EXCEEDED 或 INVALID_REPLAY），默认至少3个独立回合，首末失败相隔至少120秒。一次请求内部重试不计为多个回合。
- 正常模型输出或工具活动会清掉失败连续记录。正常完成但不发言、后台维护和日程等任务不计失败；工具参数错误、QQ发送失败、令牌鉴权、供应商余额与限流、网络和服务端错误不作为自动重建依据。
- 动作前两次核对当前映射、真实未处理且已通过消息准入的消息、全局与会话预算正常、发送额度、暂停、免打扰、会话忙碌、DSH/QQ连接和群内禁言情况。未知状态不执行。最终确认期间若出现模型进展则撤销恢复。

## 动作与边界

桥接提供最小能力：先停止旧会话及其队列，再确认归档，最后撤销映射/旧令牌并创建同群新会话。任一步失败或结果未知就停手告警；不杀桥接、DSH、QQ进程。新会话使用正常预设、角色、预算与权限边界，以bootstrap恢复正常消息处理；不复制导致本次故障的原始请求日志，不绕过准入直接发群测试消息。

本地旧会话日志和归档保留；人物档案、记忆、心情、日程、未处理消息和收据不清空，其他会话不受影响。已确认发送不重放，未知投递结果不自动重发。停止与归档失败时不创建替代会话。

每群默认30分钟冷却、滚动24小时最多2次。新会话第一次仍发生同类请求失败就停手、只提醒一次；之后真正出现模型或工具进展才解除该故障锁。中途重载遇到未决恢复也按结果未知停手，不自动再做一次。冷却和次数保存在组件state，重启、关闭再开启均不绕过。

## 本次事件的区别

群11006持续有失败事件，故“20分钟无任何事件”的原有看门狗不能识别。机械回执也不等于模型进展。根因是可选的 `dsh_session_log` 历史日志上传中有孤立UTF-16代理，导致请求整体被拒。新截断规则与停用有问题的可选日志上传属于根因修复；本组件是将来针对单会话异常的有限兜底，不能代替修复公共配置或坏数据。公共上传设置保持关闭，不能因自动恢复而再次打开。
