# 话题发起与跟进

本组件拥有话题动作选择、实际发送前校验、成功收据和冷却；环境只提供发送能力。配置位于 L 层“主动行为 → 话题发起与跟进”，全部参数可编辑。

## 主动开聊的内容选择（私聊、群聊）
仅在概率增长模型授予 proactiveCheck 主动机会、没有待答新来信时，按可用分支的 a:b 抽“延续旧话题 / 开启新话题”，不抽终止或继续等待。默认 a=0.5、b=0.2，即约71.4%延续、28.6%换题；这是内容选择，不再次决定是否唤醒。沿用同一组全局参数，不另造概率。a=b=0表示关闭这两种可选内容，不强行发送。

延续优先参考今天或上一段会话、未结话题；上一段会话可以跨日，历史时间保持原样，不把昨天的内容说成今天刚发生。AI核对最近消息，已收束、无可追问细节时可以换题，但不绕过冷却、小时上限、预算、免打扰；不重复未回答问题，不把历史当刚来信。没有历史或未结话题时不凭空选择延续。两分支冷却/上限不可用时剔除并归一化，都不可用则安静等待；不因此判定endRound。

选择绑定当前会话与 wakeConfig.lastWakeAt，新来信撤销旧代授权；重复读取提示词不重抽，不消耗实际发送次数。排程提醒、定时冒泡、B站推荐、起床问候不参与此选择。S层资料模式的可选话题抑制仍有效。

群聊被@、点名、提问或拍醒后，优先回答最近相关消息，结合相邻消息理解整段话；不靠换题跳过问题。只有空@、单独叫名字或拍一拍且没有具体待答消息时，也使用本组件的开聊话题抽签。招呼本身不算旧话题，完全没有上文时只能选择可用的新话题；图片、引用原文和未知目标@保留待答，不机械过滤。话题已经收束且没有待答内容时可自然换题；等待工具的endRound仍独立执行。

空 @ 是叫 bot 参与，不是要求用户补全的空问题。识别复用已核实的 `atSelf` 与 bot 名称，兼容群名片前缀；不会仅凭任意 `@xxx` 丢弃正文，也保留名称后紧接的实际文字、其他 @ 对象、引用和附件。即使来信批次原因是 message／budgetWeak，空招呼也可进入原有话题选择；限额和等待条件仍独立生效。当前批次有实际待答内容时先回答，不靠换题跳过；此前 bot 反复提“只 @ 不说话”的文字不能冒充未结话题。不数空 @ 次数责问，不凭空推断网络或发送故障。无当前来信、后台维护和 S 层认真回应不会据此额外开聊。

回归：`node --test scripts/test-opening-topic.mjs` 覆盖实际显示名 `@DeepSeekAI助手`、有无历史、低预算批次、历史问题优先、紧接正文、其他 @、引用及附件。

## 等待超时后的动作（私聊、群聊）
先由 life-conversation-wait 按 p、q 判定是否结束。本轮继续时，按 a=followupWeight、b=newTopicWeight、1−a−b 选择旧话题追问、新话题、继续等待。默认0.5、0.2、0.3；a、b 在0–1内且和不超过1。冷却或小时上限不满足时，该分支转为等待，不重抽。重复读取同一次超时返回同一选择；新来信撤销旧选择及发送授权。

旧话题追问包括“用户还在吗”等催回复。新话题由AI结合当前会话的实际上下文、本人档案和已确认近况寻找切入点，不把泛用话题提示当作已发生事实。不得用另起话题代替回答用户。

抽中追问或新话题后，返回给模型的指引优先要求实际发送一条具体、容易回应的消息，成功后再等待；旧话题优先接续已有细节，避免默认反复询问“还在吗”。这是软引导，不拦截再次等待、不改变权重或p/q收尾概率；对方明确忙碌、拒绝、已结束话题、缺少合适内容或发送受限时，允许继续等待或收尾，不绕过任何发送保护。

同一话题跟进冷却、新话题冷却和每小时新话题上限，同时约束普通聊天与主动聊天，独立于群聊转私聊跟进的间隔和日上限。正常回答、必要任务澄清仍可进行。主动分支使用 conversationIntent=followup|newTopic 和稳定 topicId；环境在真实发送前检查语义元数据、超时授权及短催回复句，不声称能完整识别任意自由文本的语义。

## 真实发送与主动会话
beforePrompt和超时选择不消耗额度。conversationDrive.reserve/authorize/release 保护发送，sent 只记录确认成功的收据；失败不花次数。eventId去重，episodeId合并同一波的多条消息；不同语义分别记录冷却，新话题每波只计一次。

同一波只允许一个新话题ID；该话题的多段文字仍可继续发送，另一个topicId会返回new_topic_already_chosen，避免把“同波免重复计次”误当作连续开多个新题的许可。旧收据缺少绑定ID时只参考其已记录的lastTopicId，不改原始日志或凭空补写成功。

2026-10-31：同一入站代次的主动波最多成功发送一个可选追问，预留租约也保护并发发送；成功收据才落账，失败释放。已有问题未获新来信时，同话题也不能再追加第二问，返回停止补问的明确提示；陈述续段与普通回复不受此可选话题闸门影响。识别依赖 followup 元数据及问号/常见疑问结尾，不宣称能识别全部自由文本语义。

成功的话题发起或跟进均视为主动会话：同一波只计一次，重置主动概率模型静默阶段并更新上次主动时间。不会因bot发言改变用户客观聊天意愿，也不会重置无人回复的p/q递增链；只有新来信重置该链，避免反复追问无限延长本轮。

## 群聊转私聊跟进
private_followup_send根据群内话题向本轮实际发言者私聊追问；档案需同时确认该群与其私聊关系。先确认群内回复已送达；若工具先排队，则等群内成功收据再发。已完成群内回复后调用会立即尝试，不等待下一条群消息。

全局最小间隔与单会话值取max，每日上限取min。排队不扣次数，私聊实际成功才记账。发送前持久化稳定actionId凭据；未知投递保留锁，不自动重试。目标暂停、忙碌、白名单和发送预算仍由公共环境闸门检查。

## 边界
S层资料讨论模式继续抑制可选话题；停用后不注入或执行本组件话题动作。策略状态位于组件state，调度沿用公共调度器。隔离测试不代表生产QQ发送验收。
