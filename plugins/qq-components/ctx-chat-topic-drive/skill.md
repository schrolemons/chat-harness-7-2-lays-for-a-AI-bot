# skill：会话推进（topic-drive）

## 它解决什么
模型很容易「接一句就没了」：不追问、不往下聊，或者反过来每句都追问像审讯。
这个插件把「这轮该不该追问 / 该不该起新话题」变成确定性判定，写进提示词。

## 什么时候被调用
每轮唤醒拼提示词前（`beforePrompt`）。没有来信且不冷场时不产出。

## 判定口径
- **私聊内追问 / 群聊内追问**：共享同一套语境提示；冷却和上一句问题保护仍生效，但是否追问、追问深度由模型结合关系和语气自行决定，不用固定概率抽签。
- **群聊转私聊追问**：独立由 `private_followup_send` 工具执行。若本轮实际发言者值得关心（如身体不适、压力、难处或重要经历），或小鲸鱼对其具体事情确实感兴趣、自然想知道后续，应先正常完成群聊回复，再私聊追问一句；只对人物档案同时有该群和对应私聊会话的人开放，不复述群里内容。此动作与群内选用 `qq_send_message` / `qq_reply` 是并列判断，不能互相替代。
- **起新话题**：无人来信时先由life-wake-reasons授予唯一主动机会；本组件只决定内容，不再抽第二次概率。普通回复也可以在接住当前内容后自然换题（可由topicIntent=newTopic明确选择）。尊重收尾、等待和未答问题；45分钟冷却、每小时最多2次只由真实发送消费。
- beforePrompt只读，不写桥接会话业务字段。`conversationDrive.sent({key,success,eventId,episodeId,at,kind,text,topicId})`仅在success严格为true时保存当前会话的实际追问/新话题；稳定eventId去重，episodeId合并分条次数但后续实际问题仍更新lastQuestionAt。kind可为followup/newTopic；正文带问号也会识别为实际问题。无成功发送不花冷却或额度。
- 同episode按实际语义种类分别记录followup/newTopic，整体driveCount仍只计一次；先追问再换题、反过来的顺序都保留各自冷却，新话题小时配额每episode最多消费一次。普通追问文案中的可选换题同样先过新话题冷却与小时上限，不能绕限；正常回应与必要任务澄清仍可进行。
- 宿主热加载entry的generation查询会透传到本组件拥有的conversation-drive选择器与followup-policy模块；静态依赖缓存不阻止新策略生效。
- 提示使用当前mood.modeName/styleInstruction，不固定某一种角色。语义选择器可注入selectTopic供确定性测试；不重复上一实际话题。真正完成用户请求所需澄清不受可选社交追问冷却限制。

## 配置
控制台 L 层「定时主动消息」区域提供跨会话私聊跟进开关、全局最小间隔和每日上限，以及按目标私聊session单独设置的同名值。最小间隔取max（更久），每日上限取min（更少）；不保留followUpProbability/newTopicProbability运行读取。

## 边界
- 只产出一段提示词，不发消息、不改人设。
- 判定依赖会话状态（最近消息、activeTopics、上次引导时间），不读别的会话内容。
- 停用后桥接不再注入任何追问/起话题要求。


## SCHNIE 正式模式协调（2026-10-26）

通过 schnie-core/turn-policy.mjs 共用当前逐轮路由。phi/care/现实支持模式抑制与认真回应冲突的玩梗、多条碎句、表情或另起话题要求；普通闲聊保留既有行为。仅协调提示词，不记录心理判断、不自动发送消息。S层停用后恢复普通规则。

2026-10-29：群后私聊能力传 sourceKey 和稳定 actionId（源群、目标用户、源消息时间），环境创建目标独立动作并守住目标忙碌/提醒，不借目标active回合；同动作分条共用等待与意愿去重ID。现有发送工具可附 conversationIntent=reply|followup|newTopic 和 topicId，只有实际成功才记录；问号仍来自真实发送正文。追问/新话题冷却、小时数量属于模型引导，不宣称语义硬拦截；普通回答与必要澄清不受社交追问引导阻断。
