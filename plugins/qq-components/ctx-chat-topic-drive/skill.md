# 话题发起与跟进

本组件拥有话题动作选择、实际发送前校验、成功收据和冷却；环境只提供发送能力。配置位于 L 层“主动行为 → 话题发起与跟进”，全部参数可编辑。

## 等待超时后的动作（私聊、群聊）
先由 life-conversation-wait 按 p、q 判定是否结束。本轮继续时，按 a=followupWeight、b=newTopicWeight、1−a−b 选择旧话题追问、新话题、继续等待。默认0.5、0.2、0.3；a、b 在0–1内且和不超过1。冷却或小时上限不满足时，该分支转为等待，不重抽。重复读取同一次超时返回同一选择；新来信撤销旧选择及发送授权。

旧话题追问包括“哥哥还在吗”等催回复。新话题由AI结合当前会话的实际上下文、本人档案和已确认近况寻找切入点，不把泛用话题提示当作已发生事实。不得用另起话题代替回答用户。

同一话题跟进冷却、新话题冷却和每小时新话题上限，同时约束普通聊天与主动聊天，独立于群聊转私聊跟进的间隔和日上限。正常回答、必要任务澄清仍可进行。主动分支使用 conversationIntent=followup|newTopic 和稳定 topicId；环境在真实发送前检查语义元数据、超时授权及短催回复句，不声称能完整识别任意自由文本的语义。

## 真实发送与主动会话
beforePrompt和超时选择不消耗额度。conversationDrive.reserve/authorize/release 保护发送，sent 只记录确认成功的收据；失败不花次数。eventId去重，episodeId合并同一波的多条消息；不同语义分别记录冷却，新话题每波只计一次。

成功的话题发起或跟进均视为主动会话：同一波只计一次，重置主动概率模型静默阶段并更新上次主动时间。不会因bot发言改变用户客观聊天意愿，也不会重置无人回复的p/q递增链；只有新来信重置该链，避免反复追问无限延长本轮。

## 群聊转私聊跟进
private_followup_send根据群内话题向本轮实际发言者私聊追问；档案需同时确认该群与其私聊关系。先确认群内回复已送达；若工具先排队，则等群内成功收据再发。已完成群内回复后调用会立即尝试，不等待下一条群消息。

全局最小间隔与单会话值取max，每日上限取min。排队不扣次数，私聊实际成功才记账。发送前持久化稳定actionId凭据；未知投递保留锁，不自动重试。目标暂停、忙碌、白名单和发送预算仍由公共环境闸门检查。

## 边界
S层资料讨论模式继续抑制可选话题；停用后不注入或执行本组件话题动作。策略状态位于组件state，调度沿用公共调度器。隔离测试不代表生产QQ发送验收。
