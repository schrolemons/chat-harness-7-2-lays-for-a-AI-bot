# skill：会话推进（topic-drive）

## 它解决什么
模型很容易「接一句就没了」：不追问、不往下聊，或者反过来每句都追问像审讯。
这个插件把「这轮该不该追问 / 该不该起新话题」变成确定性判定，写进提示词。

## 什么时候被调用
每轮唤醒拼提示词前（`beforePrompt`）。没有来信且不冷场时不产出。

## 判定口径
- **私聊内追问 / 群聊内追问**：共享同一套语境提示；冷却和上一句问题保护仍生效，但是否追问、追问深度由模型结合关系和语气自行决定，不用固定概率抽签。
- **群聊转私聊追问**：独立由 `private_followup_send` 工具执行。若本轮实际发言者值得关心（如身体不适、压力、难处或重要经历），或小鲸鱼对其具体事情确实感兴趣、自然想知道后续，应先正常完成群聊回复，再私聊追问一句；只对人物档案同时有该群和对应私聊会话的人开放，不复述群里内容。此动作与群内选用 `qq_send_message` / `qq_reply` 是并列判断，不能互相替代。
- **起新话题**：没人说话或对方明显收尾、且 45 分钟冷却、每小时不超过 2 次 → 按概率（默认 0.35）产出「起个新话题」；话题优先取没聊完的 activeTopic，其次内置种子池。
- 连续两次不会是同一种引导（`driveLastKind`）。

## 配置
控制台 L 层「定时主动消息」区域提供跨会话私聊跟进开关、全局最小间隔和每日上限，以及按目标私聊 session 单独设置的同名值。每项有效值取全局与 session 值的较小值；模型不暴露追问概率和深度滑杆。

## 边界
- 只产出一段提示词，不发消息、不改人设。
- 判定依赖会话状态（最近消息、activeTopics、上次引导时间），不读别的会话内容。
- 停用后桥接不再注入任何追问/起话题要求。


## SCHNIE 正式模式协调（2026-10-26）

通过 schnie-core/turn-policy.mjs 共用当前逐轮路由。phi/care/现实支持模式抑制与认真回应冲突的玩梗、多条碎句、表情或另起话题要求；普通闲聊保留既有行为。仅协调提示词，不记录心理判断、不自动发送消息。S层停用后恢复普通规则。
