# 会话花费分级（O 层）

控制台「令牌与花费」的「管理员 owner 受额度限制」对应 `ownerBudgetEnabled`，默认 `true`。设为 `false` 后，仅当前 `ownerQQ` 的私聊及从该私聊发起的独立任务豁免个人冷漠阈值、低频间隔、个人硬上限和全局硬上限；群聊、其他私聊和无归属后台任务仍受限。花费照常计入账本和全局总额。`GET /api/tokens/budgets` 返回 `owner` 设置及会话的 `exempt` 标记，`POST /api/tokens/budgets/owner` 接受布尔值并热加载组件。首次安装本功能需加载新的 bridge.js；其后切换开关无需重启。

每个 QQ 会话可以分别设置冷漠回复阈值、耗费上限和低频间隔，另有统一花费上限（含 QQ 会话与后台任务的模型调用）。花费按现有 token 账本的人民币价格计算，每晚 22:00（上海时间）开始新周期。达到前一阈值后缩短新注入的上下文并降低投递频率；达到会话硬上限后停止该会话的新模型请求，达到全局硬上限后停止桥接发起的所有新模型请求。阈值留空或设为 0 表示关闭该级限制。

硬上限触发后，只保留机械回复：每个私聊会话累计 5 条新消息（含图片消息）随机发送一条私聊词条；群聊只有真正 @ 机器人时才随机发送群聊词条。消息 ID 去重，计数按结算周期保存。普通排队消息、主动通知、图片和语音等出站在发送前再次检查额度，机械词条走专门允许的纯文本出口。词条不调用模型，默认各 30 条；控制台「令牌与花费」可编辑，`GET/POST /api/tokens/budgets/replies` 仅接受控制台令牌，修改后热加载。

`recoveryWindows.privateMessages / groupMessages / groupAtMessages` 是冷漠阶段与静默恢复共用的唯一消息窗口设置，各为1–30条、默认5条。`tokenBudget.selectWindow({key,messages})` 按原始seq/time顺序选择：私聊最近N条；群普通消息最近N条和真正@机器人的消息最近N条分别截取后合并。没有另一套weak窗口配置。

冷漠阶段的唤醒快照、agent未读/近期读取、等待返回以及组件提示词都使用同一个模型可见窗口，不再固定只取4条，也不能靠工具翻页绕过窗口。窗口外入站消息保留在管理端raw recent中，标记`budgetDisposition: outside-cold-window`并从unread摘除；不伪造seenAt/repliedAt，不要求模型为窗口外历史消息补回执。receiptWindow也不带窗口外正文。硬上限时agent消息读取视图为空；正常额度阶段不增加窗口限制，管理端仍可查看完整缓冲证据。模型视图使用Proxy，仅过滤消息读取，业务组件清理pending冒泡/任务等非消息字段仍写回真实状态。

硬上限期间，额度组件按会话在本机状态中保留最近30条入站候选（单条正文最多500字，图片只存会话绑定的暂存ID）。恢复时也调用同一个selectWindow服务，在一个模型回合内补处理；最多每分钟启动一个会话。群聊只有所选窗口中真正@了机器人时才补处理，普通消息仅作背景；无@则结清该恢复窗口。已暂存且未过期的图片随补处理回合附给模型（最多4张），过期图片标为不可查看。派发未被接受、DSH离线或仍受额度/低频限制时保留，成功接受后结清该批，避免重复补投。窗口设置不改变硬上限机械回复频率，也不与四套思考期间补话词库共用配置。

隔离验证：`node --test scripts/test-cold-window.mjs`；只使用纯组件、临时状态与fake QQ/DSH。

独立运行的网页监控摘要也在模型调用前读取全局额度；达到上限或额度状态不可用时跳过 AI 整理，使用已有的非 AI 差异处理。已经开始的模型步骤可能完成并计费，硬上限只阻止后续调用和普通出站，不能保证实际账单绝不越过阈值。

统计沿用「逐轮花费」口径：同一轮的计费步骤先合并，整轮按最后一步的时间归入周期。旧的累计投影不能确定归属日期，因此不能假装是本周期花费；控制台应标明统计不完整的情况。
