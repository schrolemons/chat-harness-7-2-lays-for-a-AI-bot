# 会话花费分级（O 层）

控制台「令牌与花费」的「管理员 owner 受额度限制」对应 `ownerBudgetEnabled`，默认 `true`。设为 `false` 后，仅当前 `ownerQQ` 的私聊及从该私聊发起的独立任务豁免个人冷漠阈值、低频间隔、个人硬上限和全局硬上限；群聊、其他私聊和无归属后台任务仍受限。花费照常计入账本和全局总额。`GET /api/tokens/budgets` 返回 `owner` 设置及会话的 `exempt` 标记，`POST /api/tokens/budgets/owner` 接受布尔值并热加载组件。首次安装本功能需加载新的 bridge.js；其后切换开关无需重启。

每个 QQ 会话可以分别设置冷漠回复阈值和耗费上限；群聊另有冷漠检查间隔，另有统一花费上限（含 QQ 会话与后台任务的模型调用）。花费按现有 token 账本的人民币价格计算，每晚 22:00（上海时间）开始新周期。达到冷漠阈值后，私聊累计达到privateWakeEveryMessages条唯一来信固定唤醒一次（默认5），合并回复1条后结束；群聊按配置间隔（默认30分钟）处理所选普通窗口与@窗口（默认5+5条），处理后结束。两者不走概率递增、不追问或延长等待，不触发思考补话；达到会话硬上限后停止该会话的新模型请求，达到全局硬上限后停止桥接发起的所有新模型请求。阈值留空或设为 0 表示关闭该级限制。

达到花费硬上限（满额）后，每条私聊来信均评估一次固定回复；群聊仅真实 @ bot 或已核实引用 bot 时评估，普通消息不回复且不占机械限频；消息ID去重，独立防刷屏默认每会话最短10秒、滚动60秒最多4条、滚动3600秒最多30条，三项同时生效，可在控制台「令牌与花费」调整。被限流的候选不排队补发，真实发送前再次核验；固定词条不调用模型。`GET/POST /api/tokens/budgets/replies` 一并管理词条和 `mechanicalLimits`，只接受控制台令牌。正常模型回合的思考/超时补话不占正式发送条数、分钟/小时上限，但必须存在真实运行且有回复资格的模型回合。冷漠与满额均禁用这两段补话。日程、冒泡、已有日记与监控通知保留无模型直投，仍服从暂停、免打扰、时效与真实收据。

`recoveryWindows.privateMessages / groupMessages / groupAtMessages` 是冷漠阶段与静默恢复共用的唯一消息窗口设置，各为1–30条、默认5条。`tokenBudget.selectWindow({key,messages})` 按原始seq/time顺序选择：私聊最近N条；群普通消息最近N条和真正@或经核实引用机器人的消息最近N条分别截取后合并。没有另一套weak窗口配置。

冷漠阶段的唤醒快照、agent未读/近期读取、等待返回以及组件提示词都使用同一个模型可见窗口，不再固定只取4条，也不能靠工具翻页绕过窗口。窗口外入站消息保留在管理端raw recent中，标记`budgetDisposition: outside-cold-window`并从unread摘除；不伪造seenAt/repliedAt，不要求模型为窗口外历史消息补回执。receiptWindow也不带窗口外正文。硬上限时agent消息读取视图为空；正常额度阶段不增加窗口限制，管理端仍可查看完整缓冲证据。模型视图使用Proxy，仅过滤消息读取，业务组件清理pending冒泡/任务等非消息字段仍写回真实状态。

硬上限期间，额度组件按会话在本机状态中保留最近30条入站候选（单条正文最多500字，图片只存会话绑定的暂存ID）。仅恢复正常额度后调用同一个selectWindow服务，在一个模型回合内补处理；最多每分钟启动一个会话。群聊只有所选窗口中真正@或经核实引用机器人时才补处理，普通消息仅作背景；无上述定向消息则结清该恢复窗口。已暂存且未过期的图片随补处理回合附给模型（最多4张），过期图片标为不可查看。派发未被接受、DSH离线或仍为冷漠/满额时保留，成功接受后结清该批，避免重复补投。窗口设置不改变硬上限机械回复频率，也不与四套思考期间补话词库共用配置。

隔离验证：`node --test scripts/test-cold-window.mjs`；只使用纯组件、临时状态与fake QQ/DSH。

独立运行的网页监控摘要也在模型调用前读取全局额度；达到上限或额度状态不可用时跳过 AI 整理，使用已有的非 AI 差异处理。已经开始的模型步骤可能完成并计费，硬上限只阻止后续调用和普通出站，不能保证实际账单绝不越过阈值。

统计沿用「逐轮花费」口径：同一轮的计费步骤先合并，整轮按最后一步的时间归入周期。旧的累计投影不能确定归属日期，因此不能假装是本周期花费；控制台应标明统计不完整的情况。

私聊计数与派发租约由reply-throttle.mjs持久化。一次接受只消耗该批次认领时的触发条数，投递等待期间新来的消息留给下一批；并发不能重复接受同一批。冷漠群聊所选批次可发至窗口条数；达到普通分钟发送上限后由传输层等待释放再续发，不能靠反复调用模型/发送工具绕过上限。

Console「令牌与花费」的私聊冷漠触发条数是全局规则、按会话分别计数，1–100整数，默认5。GET /api/plugins/detail?id=life-token-budget读取，POST /api/plugins/config提交 {id:"life-token-budget",config:{privateWakeEveryMessages:3}} 即保存并热加载。它不是上下文窗口，也不改变群聊间隔或一次私聊只回复1条的计划。修改规则保留已有计数；投递中的批次沿用认领时的扣除条数，避免热加载丢掉新来信。

引用核实在静默阶段只读取网关消息ID、所属群和发送者元数据，不把引用正文交给模型，也不绕过模型消息读取限制。引用别人、其他群、消息ID不符或目标未知均不触发机械回复。桥接将结构化quoteTargetIsSelf传入额度组件并随恢复队列保存；需要加载新版bridge.js才生效。
