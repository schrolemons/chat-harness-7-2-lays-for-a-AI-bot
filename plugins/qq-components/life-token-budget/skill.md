# 会话花费分级（O 层）

控制台「令牌与花费」的「管理员 owner 受额度限制」对应 `ownerBudgetEnabled`，默认 `true`。设为 `false` 后，仅当前 `ownerQQ` 的私聊及从该私聊发起的独立任务豁免个人冷漠阈值、低频间隔、个人硬上限和全局硬上限；群聊、其他私聊和无归属后台任务仍受限。花费照常计入账本和全局总额。`GET /api/tokens/budgets` 返回 `owner` 设置及会话的 `exempt` 标记，`POST /api/tokens/budgets/owner` 接受布尔值并热加载组件。首次安装本功能需加载新的 bridge.js；其后切换开关无需重启。

每个 QQ 会话可以分别设置冷漠回复阈值和耗费上限；群聊另有冷漠检查间隔，另有统一花费上限（含 QQ 会话与后台任务的模型调用）。花费按现有 token 账本的人民币价格计算，每天在dailyResetTime指定的北京时间开始新周期，默认22:00。达到冷漠阈值后，私聊累计达到privateWakeEveryMessages条唯一来信固定唤醒一次（默认5）；群聊按配置间隔（默认30分钟）查看所选普通窗口与@窗口（默认5+5条）；本次窗口全部是唤醒前来信，均可自由应答或整批不回复，处理后结束。两者不走概率递增、不追问或延长等待，不触发思考补话。普通聊天每份完整内容的拆分条数由ctx-chat-reply-shape统一管理，不再固定私聊只发1条。达到会话或全局硬上限后阻止相应的新聊天请求与新任务准入；已经通过检查的任务执行续权见下节。阈值留空或设为0表示关闭该级限制。

## 任务开始与执行续权（2026-11-02）

显式任务执行、传话、日程创建/修改/取消及真实到期提醒、报告查看/检索/摘要和完成汇报，需要可验证的任务来源。任务开始仍检查原有唤醒、适用费用限制和弱限频：冷漠私聊默认每5条唯一来信、群聊按配置间隔，未到准入时机不能凭任务标签提前另开调用。接手同一任务及其完成汇报整组还须占共享分钟/小时额度1点。通过检查及计点后，将准入权限持久绑定原任务范围。

已准入任务若在执行中跨过费用软阈值或硬上限，可继续完成原任务并及时汇报；原任务必要结果不被普通聊天预算截断。全部实际调用费用照常进入会话账本和全局总额。执行续权不授权无关聊天、无限新任务或超出原范围的工作；任务自报标签、更换工具、读取旧消息不能铸造新的准入权限。新任务须重新通过开始条件。既有ownerBudgetEnabled关闭时的明确管理员规则仍按该设置处理。

接手任务组共占1点，组内实际执行与完成汇报发送不重复扣点，也不受每份普通内容拆分上限限制。没有分钟/小时可用额度时，来源保持已读未处理，额度恢复后自动复查费用、唤醒、弱限频及其他开始条件，扣1点后再执行；同组续跑或重载不重复扣点。任务接手计点记录独立于QQ实际投递收据，不能把接手标记当作已送达或已回复。费用准入、任务组接手计点和真实出站回执是不同事实。权限、模式、白名单、跨会话/媒体授权、免打扰、暂停、时效、维护禁发、防重与真实回执不被豁免。

`dailyResetTime`由O层「令牌与花费」保存，格式为HH:mm（00:00–23:59），是私聊、群聊及后台任务共用的全局额度边界。`tokenBudget.period`与`assess`读取同一配置；修改后立即以新边界重算本周期，历史账本不清零、不删除。时间运算固定使用Asia/Shanghai，不随浏览器或宿主机时区变化；日记日期分界不受此项影响。保存走`POST /api/plugins/config`，仅提交`{id:"life-token-budget",config:{dailyResetTime:"04:30"}}`，组件局部热载，无需重启桥接。回归：`node --test scripts/test-budget-cycle.mjs scripts/test-budget-cycle-ui.mjs`。

普通聊天达到费用硬上限后保持安静，不发送固定预算词条、思考提示或超时补话。历史固定词条和mechanicalLimits配置保留兼容，不表示满额后仍会发送。正常模型回合的思考/超时补话须存在真实运行且有回复资格的模型回合；冷漠与满额均禁用。已准入任务可按原任务权限继续并及时汇报；日程、已有日记与监控通知的真实任务来源、无模型投递和既有守卫仍分别核验，普通冒泡不因定时而取得任务权限。

`recoveryWindows.privateMessages / groupMessages / groupAtMessages` 是冷漠阶段与静默恢复共用的唯一消息窗口设置，各为1–30条、默认5条。`tokenBudget.selectWindow({key,messages})` 按原始seq/time顺序选择：私聊先取最早仍需回应的N条，剩余位置补最近可选消息；群普通消息最近N条和真正@或经核实引用机器人的消息最近N条分别截取后合并。没有另一套weak窗口配置。

冷漠阶段的唤醒快照、agent未读/近期读取、等待返回以及组件提示词都使用同一个模型可见窗口，不再固定只取4条，也不能靠工具翻页绕过窗口。窗口外入站消息保留在管理端raw recent中，标记`budgetDisposition: outside-cold-window`并从unread摘除；不伪造seenAt/repliedAt，不要求模型为窗口外历史消息补回执。receiptWindow也不带窗口外正文。硬上限时agent消息读取视图为空；正常额度阶段不增加窗口限制，管理端仍可查看完整缓冲证据。模型视图使用Proxy，仅过滤消息读取，业务组件清理pending冒泡/任务等非消息字段仍写回真实状态。

硬上限期间，额度组件按会话在本机状态中保留最近30条入站候选（单条正文最多500字，图片只存会话绑定的暂存ID）。仅恢复正常额度后调用同一个selectWindow服务，在一个模型回合内补处理；最多每分钟启动一个会话。群聊只有所选窗口中真正@或经核实引用机器人时才补处理，普通消息仅作背景；无上述定向消息则结清该恢复窗口。已暂存且未过期的图片随补处理回合附给模型（最多4张），过期图片标为不可查看。派发未被接受、DSH离线或仍为冷漠/满额时保留，成功接受后结清该批，避免重复补投。窗口设置不授权硬上限机械补话，也不与四套思考期间补话词库共用配置。已准入任务的执行与结果汇报不以普通聊天恢复窗口重新准入。

隔离验证：`node --test scripts/test-cold-window.mjs`；只使用纯组件、临时状态与fake QQ/DSH。

独立运行的网页监控摘要开始前也读取适用的全局额度；达到上限或额度状态不可用且无原任务准入权限时，跳过AI整理，使用已有的非AI差异处理。已经开始的模型步骤以及有效原任务权限下的继续执行照常计费，硬上限不保证实际账单绝不越过阈值。

统计沿用「逐轮花费」口径：同一轮的计费步骤先合并，整轮按最后一步的时间归入周期。旧的累计投影不能确定归属日期，因此不能假装是本周期花费；控制台应标明统计不完整的情况。

私聊计数与派发租约由reply-throttle.mjs持久化。一次接受只消耗该批次认领时的触发条数，投递等待期间新来的消息留给下一批；并发不能重复接受同一批。普通聊天仍按每份内容拆分上限及动态分钟/小时限频执行，不能靠反复调用模型/发送工具绕过；任务组接手与普通聊天共享分钟/小时额度并只占1点，组内发送不重复扣点。开始条件、原任务续权与实际投递回执分别核验。

Console「令牌与花费」的私聊冷漠触发条数是全局规则、按会话分别计数，1–100整数，默认5。GET /api/plugins/detail?id=life-token-budget读取，POST /api/plugins/config提交 {id:"life-token-budget",config:{privateWakeEveryMessages:3}} 即保存并热加载。它不是上下文窗口，不改变群聊间隔或每份内容的拆分上限。修改规则保留已有计数；投递中的批次沿用认领时的扣除条数，避免热加载丢掉新来信。

引用核实只读取bridge或SnowLuma本地缓存中的消息ID、所属群和发送者元数据，不调用QQ API，不把引用正文交给模型，也不绕过模型消息读取限制。引用别人、其他群、消息ID不符或目标未知均不获得定向消息资格；费用满额仍不发送机械回复。桥接将结构化quoteTargetIsSelf传入额度组件并随恢复队列保存。

半小时检查与普通来信唤醒分离：群聊批次开始前的消息均降为optional历史资格，不继承旧必答义务；不写已读或回复戳。inputSeqs固定本批5+5收信范围，pendingSeqs只表示必答资格，两者不可混用。Console将inputSeqs内未完成消息标为“本次收信·自由回应”；通过工具补读的其他历史仍留在历史区，不进入收信。

5+5只限制默认可回复收信范围，不裁掉原始100条近期缓存。模型可读取本批开始前仍在缓存内的历史，并自主选择回复历史；来源仍需完整读取、明确绑定及真实成功发送凭据。唤醒后新到的人类消息本批不可见，保留下一批。窗口投影不删除缓存、不推进虚假已读水位；旧outside-cold-window标签仅在仍保留的原记录上解除，不重建缺失原文。私聊待答队列沿用40条缓存保护与顺序规则。

定时调度以新候选数而非必答数判断是否需要检查。批次被DSH接受后单独保存检查水位，无新来信的可选窗口不重复消耗模型调用；该水位不等于已读或已回复。快照受字符预算节选，但补读范围以接收时冻结的批次/历史截止水位为准，不能因节选缺失而永远无法补读。
