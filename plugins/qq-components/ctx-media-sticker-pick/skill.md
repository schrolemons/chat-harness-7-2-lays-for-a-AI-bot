# skill：表情候选（sticker-pick）

## 它解决什么
模型面对一长串表情备注，容易反复发同一张，或者挑一张完全不搭的。
这个插件把「这轮哪几张最贴语境」先算好，只给 3 个候选，模型只需选或不选。

## 什么时候被调用
每轮唤醒拼提示词前（`beforePrompt`），且必须满足：
- 收藏表情功能已启用（`stickerAllowed !== false`）；按语境抽出候选后，每轮尽量由模型选一张发送；候选不合适时可用消息正文 emoji/颜文字补位；
- 有收藏表情可挑。

## 打分口径
- 语境关键词命中标签（吃/牛奶/海洋/累/生气/夸/哭/告别/问号…）+2～3；
- 当前「小鲸鱼／正太小肥鱼」系列 +1；旧人设系列不自动推荐；
- 越久没发越靠前，用得太多轻微降权；
- 30 分钟内发过的重罚（-3）；
- 没备注的降权；
- **正事/情绪话题 → 直接劝退，不给候选。**

## 配置与状态
`config.limit`（候选数，默认 3）；最近一次候选写在 `state/plugins/sticker-pick.json` 的 `last`。

## 边界
只排序不发送；每轮向模型提供语境候选，模型尽量选一张发送，并与消息正文 emoji/颜文字统一考虑；只有候选不合适或严肃语境才不发收藏表情。


## S 层资料讨论与关怀协调

通过 personal-core/turn-policy.mjs 共用当前逐轮路由。discussion/care/现实支持模式抑制与认真回应冲突的玩梗、多条碎句、表情或另起话题要求；普通闲聊保留既有行为。仅协调提示词，不记录心理判断、不自动发送消息。S层停用后恢复普通规则。
