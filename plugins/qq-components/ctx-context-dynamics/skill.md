# ctx-context-dynamics

按宿主提供的当前心情形态与表情配置输出动态提示；维护回合不注入，不在这里另抽表情概率。

插拔、配置和验收参见 docs/guides/PLUGIN_RUNTIME_CONTRACT.md。运行 npm run test:plugin-audit，测试使用隔离文件和模拟端点。


## S 层资料讨论与关怀协调

通过 personal-core/turn-policy.mjs 共用当前逐轮路由。discussion/care/现实支持模式抑制与认真回应冲突的玩梗、多条碎句、表情或另起话题要求；普通闲聊保留既有行为。仅协调提示词，不记录心理判断、不自动发送消息。S层停用后恢复普通规则。

2026-10-29：心情块仅渲染 moodState 的 modeName、score、styleInstruction、配置规则与真实 history；不重算高低阈值，不重复规定发送条数。无心情服务时不编造分数。

2026-10-30：manifest.order=-20，默认先输出当前形态，靠近前置人设卡；自定义插件排序可覆盖。心情提示不被S层关怀路由跳过，表情仍服从该路由。风格和示例仅来自心情配置，按宿主分块，不截成500字；此组件不提供第二套台词。

聊天风格是核心：`chatExpression.current({key})` 只返回该会话最近一次 beforePrompt 生成的受信当前形态、管理员风格与完整示范；不包含表情候选、用户原话、分数历史或记忆。维护回合清除缓存，不复用上轮风格。context v2 将稳定行为规则与当前形态拆开：规则位于稳定 user 资料，当前形态、风格和完整示范随动态状态变化后置更新。系统只保留固定的解释与表达优先规则，不再把本轮心情数值拼入角色卡；`roles/*` 逐字不变。普通与临界形态只发送当前选中的一套风格。
