# skill：传话组件（life-relay-message）

## 它解决什么
以前「给管理员带句话 / 问问你们管理员」直接在 `bridge.js` 的入站分支里用两条正则 + 一大段流程处理：
改说法要动主程序、没法单独开关、也没法在管理页看状态。现在整条链路是一个 L 层组件。

## 什么时候被调用
`relayIncoming`：桥接收到一条**私聊**消息、且该会话在白名单内（owner 或允许的私聊）时调用。
组件返回 `{handled:true}` 后，桥接不再把这条消息交给 AI 回合；返回 `null` 则消息照常进入 AI。

## 能识别什么
- 给/跟/和/对/向 X 带话、捎话、传话、递话（`给十二捎句话，晚安`、`给我向十二带句话`）
- 传话给 X / 转告 X / 转达给 X / 告诉 X
- 问问 X / 问一下 X / 打听一下 X（弱意图：目标解析不到时当普通聊天，不拦）
- 给/跟/和/对 X 说一声 / 说句话 / 说个事
- X 可以是：别名（config `socialV2.relayAliases`，如 `十二`）、QQ 号、`private:xx`/`group:xx`、
  白名单会话里出现过的昵称/印象名、以及「管理员/老板/主人/群主」→ owner。
- 解析规则在 `src/relay-intent.js`，回归：`npm run test:relay-intent`。

## 流程
1. 一句话带内容（`给管理员带句话，晚安`）→ 直接转达并回执。
2. 只说人不说内容（`给管理员带句话`）→ 记 pending，提示「下一条消息发内容」，下一条原样转达。
3. 名字找不到 → 记 pending，提示补 QQ 号/群号；下一句是号码就补全发送。
4. 等待补充的传话超过固定 10 分钟自动作废。
5. 非管理员同一发起会话的两次传话至少间隔 `config.minIntervalMin` 分钟（默认 10 分钟）；管理员不受此限制。原有每小时最多 6 条限制仍生效。
6. 若当前私聊消息附带图片，桥接先把它暂存到该会话，再由同一传话链路投递图片；正在等待传话内容时，下一条图片也可作为内容。

## 桥接给的环境能力（不直连 QQ）
- `resolveRelayTarget(name)`：白名单/别名/角色称呼 → 目标 key（越权目标返回 null）。
- `relaySend({fromKey,targetKey,name,body,imageIds})`：文字走内容闸门，图片按会话资源 ID 发送；含非 owner 每小时限频、白名单二次校验、回执及活动日志。本机图片不能跨会话传送。
- `sendSessionText(key, text)`：给当前会话发提示（等待内容/补 QQ 号等）。

## 边界
- 只处理**私聊**且**白名单**会话（`payload.allowed` 由桥接判定）；群聊不提供传话入口。
- 目标必须仍在白名单（`relaySend` 二次校验），群发/越权会被拒绝。
- 内容一律按「外部文本」过闸门（违规拒收、注入特征中和），不因来自 owner 就绕过。
- 组件只管「传话」；「向 harness 反馈」仍是桥接的 owner 专属逻辑。
