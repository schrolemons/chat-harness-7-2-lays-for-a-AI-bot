# 按 QQ 号管理 JSON 人物档案

## 存储与注入
- QQ 号是唯一主键；档案不依赖好友关系或 session。档案存放在本机 state/person-profiles.json。
- 每人一份可扩展 JSON。固定字段为 routine_food、hobbies、relationships、catchphrases，每项都是字符串；可以增加新的字符串字段。未传入的键保留，显式传空字符串清空内容。
- 插件首次加载时只迁移一次旧 user-profiles.json；之后读写只使用新 JSON。旧 notes/fields 数组模式、旧人物卡注入及分享条数上限均已停用。
- 私聊自动注入当前 QQ 本人的档案。群聊不自动注入任何成员档案。

## Bot 工具
- profile_get({ userId, key })：私聊读取本人；群聊只允许读取当前真实发言者，并返回四个固定字段。
- profile_update({ userId, key, profile, deleteKeys })：更新字符串字段、添加扩展字段，或通过 deleteKeys 删除扩展字段。
- profile_delete({ userId, key })：删除一整份 QQ 档案及元数据。
- profile_snapshot({ userId?, key? })：管理员读取档案索引，供管理界面和明确的跨档案任务使用；不会注入上下文。

## 权限与信息来源
- 非管理员私聊只能操作本人；群聊只能操作本轮实际发言者。只要目标本人在当前会话亲自表达了信息，就可直接提取写入，无需额外确认口令。
- 群聊工具可按需读取、修改四个固定字段（含 routine_food），但不会自动把档案注入群聊。
- 管理员私聊可按明确 QQ 号跨档案读取、修改或删除；控制台管理员也可管理任意 QQ 档案。
- 不得把群友转述、他人猜测或引用内容当作档案对象本人表达的信息。

## 信息归属
- 本组件保存最稳定、最权威的人物结论。今日会话画像与短窗口行为印象不能覆盖档案；本人明确更正经核对后更新。原话语境留会话事实，待办只留当前事务，日记只展示；作息冒泡从本档案读取，不复制一份作息台账。
- 每个字段只写档案对象本人资料。人际关系可记录该人与他人的关系和本人明确表达的互动边界，不得复制关系对象自己的资料。
- 作息饮食只会自动注入本人私聊。作息冒泡服务从 routine_food 字符串读取时间；显示名和会话关联保存在同一 JSON 的 people 元数据中。
- 档案可先于好友关系建立，也不会因群聊/私聊 session 不同而重复。
