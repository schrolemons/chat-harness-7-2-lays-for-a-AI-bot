# 语义时间约定与免打扰

识别归模型：用户说「别打扰 / 我上班 / 最近忙 / 晚上聊 / 改天 / 改个时间 / 取消 / 我回来了」时，自己判断这是哪种约定，把含糊时间补问清楚，再调用 `qq_availability` 登记（不再靠关键词或固定格式）。

- `action="set"`，`kind="daily"`：每天固定免打扰，`windows=[{start:"HH:MM",end:"HH:MM"}]`，可多段、可跨午夜（如 22:00–08:00）。
- `kind="quiet"`：一次性免打扰，传带时区的 `startISO` / `endISO`。
- `kind="later"`：约好稍后联系一次，传带时区的 `contactISO`。
- `kind="indefinite"`：现在不想聊又没给结束时间；用户再次直接找来时自动解除。
- 改期＝重新 `set`（替换旧约定）；取消用 `action="cancel"`；不确定当前约定用 `action="query"`。
- 用户明确提前回来、恢复聊天，且本次稍后联系已不再需要时，用 `action="returned"` 并传本次 `planId`（来自 `set` 的 `planId` 或 `query` 的 `plan.id`）。只撤销匹配的 `later` 约定；过期编号不得撤销新约定。其他免打扰计划不因此取消。
- 是否回来由你结合用户实际表达判断，不按固定分钟数，也不把单条发言、引用或转述自动当成回来。普通主动行为继续遵守已有的限频规则，这里不另设“最近联系保护期”。

登记成功后用一句话确认具体时间，不要只嘴上答应，也不要把约定写成普通轻量记忆（旧格式会被桥接拒绝并提示改用本工具）。

免打扰到期只解除、不主动问候；只有明确约了联系才到点唤醒一次。用户自己主动发来的消息仍可回应。引用、翻译、转述、否定取消的文字不能直接当作约定。

`state/plugins/life-user-availability.json` 保存计划、变更与执行状态；重启后会重新注册未触发的任务，已触发/过期/已取消的不重复。控制台「唤醒与会话 → 免打扰时段（按会话，只读）」展示当前计划。

验证：`npm run test:scheduler`（含 test-availability.mjs）。
