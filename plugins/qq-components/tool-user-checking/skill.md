# 管理员桌面便签与运行自查

管理入口：O层 → 桥接控制 → 管理员桌面便签。沿用唯一组件总开关；关闭会停止状态工具、悄悄话、程序故障记录和待写重试。文件与字数设置默认折叠，开关默认直接可见。

`user_checking(action="status")` 只读运行指标；`action="note"` 追加悄悄话或有事实依据的难缠故障摘要。不得读取其他私人文件、覆盖或删除便签、写入令牌和密钥，或把便签内容转发到QQ。工具名和两个动作保持一致，不增加重启或任意文件权限。

调用额度变化可自然写成悄悄话：携带milkEventId时，由milkStock核对事件是否仍有效、是否已经写过，成功追加后才确认。相同事件在不同私聊或群聊重复请求不会再写；过期ID拒绝而不冒充新变化。普通note不带该字段时保留原行为。

每次真实桥接进程启动，桥接在组件加载后调用desktopNotes.recordStartup，追加本次启动时间、距上次启动的间隔和一句轻声提醒；onTick负责写失败后的重试。启动身份使用PID加进程timeOrigin，同进程热载/重复调度不另写。首次启用若桥接已经运行了一段时间，明确标为“开始记录这次桥接启动”，不伪称刚重启。无需LLM；总开关关闭则不写，重启能力本身仍不授予bot。

桌面文件仍由 `noteFileName` 指定，只接受纯文件名，统一使用txt；不接受目录。悄悄话原文与自动故障记录共用该文件、只追加并附时间戳。普通便签超过上限会拒绝写入；自动故障摘要在文本层按完整字符缩短后再追加。

程序侧 `desktopNotes.reportIssue` 服务接收受控故障元数据：稳定标识、会话、阶段、首次发现、摘要、影响与排查方向。同一故障的同一阶段只排队一次；待处理、恢复失败和恢复记录分别追加。内容去除凭据，不携带用户聊天原文。写入失败保留持久队列，每分钟重试，不把失败当成功。

`obs-session-recovery` 只有在排除限额、静默、等待、QQ禁言等情况，确认持续模型请求故障后，才报告程序便签；恢复无效追加失败说明。模型重新产生有效输出或工具活动时只写“模型链路恢复”，不把它等同于QQ发送成功。其他难缠bug可由bot使用原有note动作主动记录，但应避免重复程序已经写入的同一问题。

验证：`node --test scripts/test-desktop-bug-notes.mjs scripts/test-session-recovery.mjs scripts/test-session-recovery-console.mjs`。文件写入测试使用独立临时桌面；桥接隔离测试关闭真实桌面写入组件，不向管理员桌面投放模拟故障。
